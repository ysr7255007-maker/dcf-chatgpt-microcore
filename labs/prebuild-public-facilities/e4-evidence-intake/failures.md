# E4 失败路径与坑清单

## F1 — "发完即忘"在背压下制造假丢失（继承 E0 F4，本实验再次独立复现）

- 现象：首版 SyntheticProvider 交付失败后丢弃事件，storedCount 永远达不到真值。
- 解决：生产者持有未确认事件，tick 重试（ack 语义）。
- 教训：这是两个独立实验中重复出现的同一类错误 → 正式 Intake 契约必须把
  "交付失败 = 生产者继续持有"写成接口约定，而不是实现细节。

## F2 — 慢下游模拟必须与生产者重试联动

- 现象：T6 首版测试只 pump 不 advance，背压滞留事件无人重试，误判为丢事件。
- 教训：背压是生产者-消费者双方的协议；测试必须同时驱动两侧，
  否则会把"测试缺陷"误读成"系统缺陷"。

## F3 — 生命周期状态机的非法迁移必须显式拒绝

- 现象：未 configured 直接 start 的调用路径在首版静默通过。
- 解决：transition() 校验 from 集合，非法迁移抛错（T1 断言）。
- 教训：Source 监管的可靠性来自"不允许抄近路"，HA 状态机的价值正在于此。
