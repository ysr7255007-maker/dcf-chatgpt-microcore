# DCF macOS 原生公共能力黑洞勘探任务书

日期：2026-08-05  
任务性质：架构勘探 + 本机运行时验证  
执行方式：先一次 Plan 模式本机勘探，再连续执行；Plan 只有战术规划权

---

# 1. 目标

不要调查“macOS 有哪些 API”。

真正要回答：

> **macOS 已长期维护哪些公共事实、索引、生命周期、动作和资源边界，可以让 DCF 少维护一整层 watcher、connector、index、daemon、状态机和适配代码？**

寻找的是“原生公共能力黑洞”：

> 一个系统已经存在的公共结构，能够同时吸收多个原本需要 DCF 自己实现的功能和接缝复杂度。

成功标准不是 API 数量，而是：

```text
复杂度吸收率高
跨功能复用高
事实所有权清晰
组合残差低
长期依赖薄
真实运行成本低
```

最高原则：

> **不要寻找最深的系统入口，寻找最能让 DCF 少造东西的系统入口。**

> **探索态可以很重，稳定态必须尽量薄。**

> **系统尽量拥有现实，DCF 自己拥有认知。**

# 3. 当前机器前提

1TR / Boot 级实验能力已经通过正常重启后的独立复核：`behavior_passed`。

当前同时具备：

```text
SIP disabled
Permissive Security
custom kernel / BootKC 能力入口已开
third-party kext / AuxKC 能力入口已开
CTRR enforcement disabled
boot-args filtering disabled
SSV / authenticated-root disabled
Research Guests enabled
FileVault Off
```

当前没有：

```text
第三方 kext
custom kernel / custom BootKC
系统卷 patch
Apple framework / daemon / binary patch
实验 boot-args
custom SSV snapshot
```

因此本任务不再把“继续打开权限”当主要问题。

不得因为权限已经开放就追求更深 hook。

# 4. DCF 需要的现实能力地图

## 4.1 现实观察

DCF 长期需要低成本知道：

```text
用户向电脑表达了什么
当前使用什么 App
何时切换上下文
文件世界发生了什么变化
AI / Agent 对机器做了什么
真实副作用是否发生
系统何时睡眠、唤醒、挂载、退出
某项工作真正影响了哪些现实资源
```

但不要求录屏一切、记录所有键盘、同步全部系统日志或永久保存所有底层事件。

优先寻找：

```text
高语义
事件驱动
增量消费
系统本来就在产生
DCF 离线后仍能部分补读
成本接近真实有价值活动量
```

## 4.2 查询与定位

DCF 需要回答：

```text
最近什么发生了变化？
现在什么存在？
哪些文件与当前材料有关？
某段历史大概来自哪里？
某 Agent 刚碰过什么现实资源？
从上次游标以后发生了什么？
```

如果系统已经可靠维护普通索引、变化游标、App 生命周期和资源身份，DCF 不复制第二份权威事实。

## 4.3 行动

未来 DCF 会读取 / 修改文件、调用 App、控制浏览器、执行开发工具、启动任务和操作共享资源。

优先级：

```text
系统级语义动作接口
>
App 正式暴露的系统能力
>
稳定 Accessibility 语义
>
UI 自动化
>
视觉 / OCR
```

## 4.4 Effect 与执行收据

Agent 自报“做完了”不能直接成为现实事实。

希望形成：

```text
Action Intent
↓
真实执行
↓
现实 Effect
↓
独立系统观察 / Receipt
↓
结果回注 Logical Operation
```

重点寻找跨 Codex、OpenCode、DCF 自研执行器、普通 shell 等来源共同成立的机器动作边界。

## 4.5 生命周期

macOS 优先负责：

```text
进程生命
按需启动
空闲退出
IPC
权限宿主
```

DCF 负责：

```text
Job 为什么存在
语义进度
结果
失败
恢复
认知意义
```

## 4.6 活动时间骨架

不同来源需要共享低成本现实背景，但时间接近不等于因果或项目关系。

寻找系统已经维护的前台 App、睡眠唤醒、使用分段等活动骨架，避免每个来源重写 session detector。

---

# 5. DCF 自己必须拥有的边界

macOS 不拥有用户认知。

系统事件不能自动回答：

```text
为什么这些现实属于同一个长期问题
用户目标是什么
哪几个历史片段后来被重新理解为同一条路线
当时怎样理解
后来为什么改变理解
```

禁止：

```text
前台 App → 自动解释为当前项目
路径 → 自动解释为用户目标
时间邻近 → 自动解释为因果
Agent 自报结果 → 自动解释为现实成功
系统事件 → 自动升级为认知事实
```

---

# 6. 已经确定的架构倾向

本轮不得重新投票：

1. 长期持久世界与 Becsy / ECS 活动世界分离；
2. 少数高自由度 AI 吸收未知，大量已理解路径下沉为高级语义状态机；
3. 成熟 Agent Runtime 与 DCF 自研执行核并存；
4. 稳定高频模式通过真实轨迹逐渐下沉；
5. Logical Operation 与 Physical Execution 分离；
6. Effect Projection 只抽取稳定的资源 / 读写 / 顺序语义；
7. Effect 未知时仍可执行，但禁止擅自去重、合并和重排；
8. 外部 Agent 一旦碰共享现实资源，要么获得隔离世界，要么进入 DCF 资源 / Effect 边界；
9. 探真工具用于发现事实，不自动成为长期承重墙。

---

# 7. 种子候选

以下是起点，不是限制名单：

- `FSEvents + Spotlight`：文件变化 + 当前文件世界；
- `NSWorkspace`：实时活动时间骨架；
- `CoreDuet / KnowledgeC`：系统保存的活动历史候选；
- `InputMethodKit / Text Input System + Unified Logging`：用户最终文字提交候选；
- `Endpoint Security / eslogger`：现实 Effect / Receipt 候选；
- `launchd + XPC`：运行生命周期与 IPC；
- `App Intents / Shortcuts / Apple Events / ScriptingBridge`：跨 App 高语义行动；
- Accessibility：结构化 UI 增益与兜底；
- ScreenCaptureKit / OCR：末端视觉兜底。

Plan 阶段必须主动寻找任务书未列出的更高杠杆公共能力，但只有可能吸收真实 DCF 复杂度时才进入候选池。

# 8. 五道 Gate

## Gate 1 — Role Discovery

先列 macOS 已经替应用维护的公共现实岗位，例如：

```text
变化历史
当前索引
活动上下文
用户文字提交
进程生命周期
现实 Effect
资源身份
跨 App 动作
系统 IPC
掉线补读
```

不要先给熟悉 API 授予冠军。

## Gate 2 — Leverage Discovery

对每个候选问：

```text
DCF 可以少造什么？
它能同时服务几个岗位？
减少的是代码，还是更深的状态所有权 / 同步复杂度？
未来增加更多来源时收益是否继续增长？
```

## Gate 3 — 组合架构

不能只报告 A/B/C 单项好用。

必须回答组合以后：

```text
谁拥有权威事实？
谁只观察？
谁拥有历史？
谁拥有当前状态？
谁允许现实 Effect？
谁负责恢复？
身份是否天然一致？
时间是否协调？
是否产生双写 / 状态镜像 / 大量映射？
```

## Gate 4 — Runtime Proof

高价值候选按不确定性和价值做真实本机实验，至少覆盖必要的：

```text
事实纯度
覆盖率
增量消费
掉线恢复
CPU / 内存 / I/O
存储增长
休眠唤醒
异常退化
版本脆弱点
```

## Gate 5 — Architecture Promotion

最终只能定位为：

```text
A 正式公共底座
B 辅助公共能力
C 探真 / 研究仪器
D App / 来源专用适配
E 淘汰
unverified 尚未验证
```

不要求一定出现 A。

# 9. 必须研究的组合

## 文件世界

```text
FSEvents + Spotlight + 必要时少量内容读取
```

验证能否删除全盘扫描、重复普通索引与 watcher。

## 活动时间骨架

```text
NSWorkspace + CoreDuet / KnowledgeC 候选
```

验证“实时发生什么 + 系统保存过什么”是否能共同吸收来源级 session detector。

## 用户表达

```text
Text Input System / InputMethodKit
+ 窄 Unified Logging 或更稳定接缝
+ 活动上下文
```

目标是低成本获得“什么时候、在哪个 App、提交了什么最终文字”的回忆锚点。

## Agent 行动 / Effect

```text
Logical Operation / Action Intent
↓
现实执行
↓
Endpoint Security / 其他系统事实面
↓
Receipt
↓
结果回注
```

系统能力成立与 DCF 正式客户端可获得性必须分开裁决。

## 生命周期

```text
launchd + XPC + Becsy World + 持久 Job/Run Receipt
```

目标是没有双重权威。

## 跨 App 行动

```text
App Intents / Shortcuts / Apple Events
↓
Accessibility
↓
UI / OCR fallback
```

验证能否形成稳定退化梯度，而不是每个 App 从零造 connector。

# 11. Plan 模式权限

只进行一次主要 Plan。

Plan 可以：

```text
读取本机与仓库
查询系统文档 / headers / frameworks / man page
补公共能力候选
设计实验
安排依赖和并行顺序
用最小探针优先否决弱候选
```

Plan 不可以：

```text
重新定义 DCF
改变认知关系边界
重新决定 Becsy / ECS 是否采用
把成熟 Agent Runtime 与自研执行核重新变成二选一
重新讨论是否应该关闭 SIP
因为某个 API 好用就修改产品目标
把任务收缩成某一个 API 的单点验证
```

Plan 输出必须包含：任务理解、DCF 能力地图、macOS Role、候选池、实验优先级、晋级/降级证据、可直接执行的计划。

除非发现任务书关键前提错误、机器状态严重不一致、会不可逆修改系统本体或改变事实所有权，否则 Plan 完成后直接执行，不再无限 Plan。

# 12. 证据与实验纪律

统一使用：

```text
observed
hypothesized
implemented_unverified
runtime_verified
behavior_passed
failed
not_tested
```

一次事件出现只证明 `observed` / `capability_observed`，不能直接证明正式架构成立。

优先使用系统现有工具、公开 API 和最小探针。

临时探针可以丑，但必须与正式底座分离。

除非另有独立架构裁决，不得：

```text
patch 系统卷
替换 Apple framework / daemon / binary
安装长期自定义 kernel
维护 custom BootKC
无需求安装常驻自定义 kext
```
