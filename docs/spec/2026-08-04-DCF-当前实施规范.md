## 0.2 规范用语

- **必须**：违反即不满足当前规范。
- **禁止**：出现即判定为错误实现。
- **当前裁决**：已经完成讨论 / 实验，不再由普通实现任务重新投票。
- **实验位**：方向允许，但是否晋级必须由真实 DCF 数据与行为证据决定。
- **可重算投影**：删除后可以由正式权威重新生成，不能反向成为第二份事实权威。
- **正式认知**：已经经过用户确认或其他明确授权进入长期认知历史的内容。
- **事实**：某个来源能够直接证明的现实，不包含 AI 为了故事顺畅补出的意义。
- **未知**：当前证据不能证明；未知不得伪装成否定或肯定。

```text
概念
状态
动作
日志
任务
测试
```

> **英语和外部协议停在边界；DCF 自己拥有的世界，优先使用用户可以直接理解和验收的语言。**

# 1. 当前 DCF 到底是什么

DCF 是：

> **长期个人认知基础设施。**

它不是聊天记录归档器，不是个人知识库换皮，也不是“把所有人生数据塞进 AI”的记忆模型。

DCF 试图长期维护三类不同世界：

```text
现实世界
→ 真正发生过什么

认知世界
→ 我当时怎样理解、后来怎样重新理解

行动世界
→ 基于当前认知决定做什么，并重新接受现实反馈
```

最重要的长期闭环是：

```text
现实发生
↓
系统 / 来源留下事实
↓
机器把事实变成人与 AI 都可重新进入的材料
↓
AI 起草当前理解
↓
用户回看、修改、补充、重新理解
↓
正式认知进入长期历史
↓
未来的新问题重新查询过去
↓
发现新的关系 / 知识 / 项目 / 可行组合
↓
必要时形成行动
↓
现实继续发生
```

因此 DCF 的核心分工是：

```text
系统负责现实
机器负责提纯与翻译
AI 负责开放理解
用户负责最终校准
数据库负责长期锚定
查询负责未来重新发现关系
求解器负责明确条件下的确定组合
时间负责持续提供新现实与新解释机会
```

# 2. 当前总体架构：六个世界，不相互冒充

当前 DCF 总体可以画成六层：

```text
┌────────────────────────────────────────────┐
│ 6. 行动与执行世界                          │
│ 任务 / Agent / Job / Effect / Reality      │
└───────────────────▲────────────────────────┘
                    │
┌───────────────────┴────────────────────────┐
│ 5. 确定求解世界                            │
│ 约束编译 → SMT / 专用求解器                │
└───────────────────▲────────────────────────┘
                    │
┌───────────────────┴────────────────────────┐
│ 4. 查询诱导语义场                          │
│ 词法 / 稠密语义 / 后期交互 / 联合阅读      │
└───────────────────▲────────────────────────┘
                    │
┌───────────────────┴────────────────────────┐
│ 3. 锚定认知世界                            │
│ SQLite：认知对象 / 不可变修订 / 锚点 / 关系│
└───────────────────▲────────────────────────┘
                    │
┌───────────────────┴────────────────────────┐
│ 2. 认知形成世界                            │
│ 个人叙事 AI → 用户审核 → 正式认知          │
└───────────────────▲────────────────────────┘
                    │
┌───────────────────┴────────────────────────┐
│ 1. 公共现实与事实世界                      │
│ macOS / 来源系统 / Git / Agent Reality     │
└────────────────────────────────────────────┘
```

它们的权威必须严格分开：

```text
现实事实
≠
AI 对现实的理解
≠
用户确认后的认知
≠
搜索模型临时认为“相关”
≠
求解器在给定约束下计算的解
≠
行动完成后真正发生的现实结果
```

任何实现只要把其中两层偷换成同一个东西，就会制造长期认知污染。

# 3. 三个最高不变量

## 3.1 系统拥有现实，DCF 拥有认知

如果操作系统、来源软件、Git 或其他成熟系统已经维护某项确定现实，DCF 优先消费，而不是复制第二套权威。

例如：

```text
文件变化历史
→ FSEvents

当前文件索引
→ Spotlight

前台活动骨架
→ KnowledgeC / NSWorkspace

用户向 App 最终提交的文字
→ IMK + Unified Logging

Agent 的机器副作用收据
→ Endpoint Security / eslogger

工程版本事实
→ Git / GitHub

DCF
→ 为什么这些现实后来被理解成同一个问题、项目、经验或原则
```

核心原则：

> **不要寻找最深的系统入口；寻找最能让 DCF 少造东西的系统入口。**

---

## 3.2 认知只能追加变化，不能静默覆写历史

必须始终区分：

```text
当时发生了什么
当时怎样理解
后来怎样重新理解
现在又怎样理解
```

允许：

```text
2026：当时认为 A
2027：经历 B 后重新理解为 C
2028：又发现 C 只在条件 D 下成立
```

禁止：

```text
直接把 2026 的 A 改成 2028 的最终答案
```

核心原则：

> **认知永远记录在它产生的时间点；它可以引用任意过去，但不能回写过去。**

> **理解的改变本身就是叙事。**

---

## 3.3 功能增加可以，接缝增长不可以

DCF 允许未来拥有大量独立功能：

```text
个人叙事
项目叙事
Wiki
知识卡
语言弹药
项目涌现
架构选择
行动任务
各种未来认知工具
```

但新增一个功能时，已有功能不应被迫知道它的存在。

理想增长：

```text
功能数量 N 增长
↓
每个功能只依赖少数公共能力
↓
已有功能之间的调用边数量基本不增长
```

错误增长：

```text
项目叙事更新
→ 主动调用 Wiki
→ 主动调用知识卡
→ 主动通知语言弹药
→ 主动刷新项目推荐
```

正确增长：

```text
正式认知进入公共认知世界
↓
未来功能按自己的问题查询
↓
各自独立生成自己的结果
```

核心原则：

> **功能块之间共享世界与公共能力，不共享彼此的内部理解。**

# 4. 产品宿主：独立 macOS App

DCF 当前主产品形态确定为：

> **独立 macOS App。**

浏览器插件、Codex / IDE 适配器、系统探针都只是来源接缝或能力适配器，不承担 DCF 主产品身份。

App 同时拥有：

```text
完整形态
侧边栏形态
悬浮球形态
```

三种 Surface（界面投影）共享同一批业务状态和动作。

原则：

> **功能身份、业务事实和动作语义只有一份；Surface 只是投影。**

禁止：

```text
完整形态一套业务状态
侧边栏一套
悬浮球再一套
```

---

## 4.1 完整形态

完整形态承担：

```text
完整个人叙事历史
认知查询
来源追溯
修订历史
项目 / 知识 / Wiki 等独立功能
运行管理
设置
诊断
Surface 编排
```

任何正式能力最终都必须能够从完整形态找到、理解和管理。

---

## 4.2 侧边栏

侧边栏是：

> **可组装的高频工作投影。**

适合：

```text
待复盘个人叙事
当前项目摘要
当前任务
Agent 状态
少量高频知识 / 快捷动作
```

但具体组件由已注册功能决定，不在宿主中硬编码未来功能名单。

---

## 4.3 悬浮球

悬浮球只承担：

```text
极少量值得持续存在的状态
+
极少量高价值快捷动作
+
进入侧边栏 / 完整形态的入口
```

禁止把它做成“未读债务计数球”。

---

## 4.4 功能注册与 Surface 编排

每个功能块声明自己提供：

```text
功能身份
状态
动作
完整页面
首页 / Dashboard 贡献（如果有）
侧边栏贡献（如果有）
悬浮球贡献（如果有）
设置入口（如果有）
专用原生交互（如果有）
```

宿主负责：

```text
发现当前功能
启用 / 禁用
导航
排序
组合
Surface 配置
功能重载后的重新编排
```

原则：

> **功能块拥有展示能力；宿主拥有展示秩序。**

# 5. 功能块与 World：自由发生在内部，秩序发生在边界

一个完整功能块至少回答：

```text
它是什么？
长期事实由谁拥有？
它允许什么动作？
依赖哪些公共能力？
是否需要独立 World / Job？
怎样进入三个 Surface？
怎样失败？
怎样恢复？
怎样现实验收？
```

DCF 当前继续允许：

```text
Bun / TypeScript
Swift / SwiftUI / AppKit
WKWebView
Becsy
状态机
第三方库
专用算法
```

在功能内部自由组合。

但公共边界必须稳定。

原则：

> **World 规定所有权与依赖边界，不规定内部实现方式。**

> **World 是隔离单位，公共能力是复用单位，ECS 是优化手段，不是领域建模宗教。**

> **限制关系，不限制能力。**

只有真正需要安全 / 故障 / 不可信代码物理隔离时，才升级到独立进程、XPC、sandbox 等更强边界。

macOS 底层能力调查已经完成，不再作为普通实现任务重新讨论。

当前正式公共现实组合：

```text

屏幕 / OCR 常驻全量现实面
```

## 6.1 事实层的主体归因纪律

必须严格区分：

```text
系统观察到状态变化
≠
证明是用户主动造成
```

例如只证明：

```text
Chrome 当前标签页 URL：A → B
```

只能保存 / 翻译为：

> Google Chrome 当前标签页 URL 从 A 变为 B。

不能保存成：

> 用户打开了 B。

同理：

```text
前台应用：Chrome → Codex
```

不能自动升级为：

> 用户切到 Codex 继续推进 DCF。

项目归属、目标、因果、重要性、价值都不属于底层事实层。

---

## 6.2 多源事实不粗暴去重

同一现实可以由多个来源分别证明不同侧面：

```text
IMK
→ 用户向 Codex 提交了什么

KnowledgeC
→ 当时前台工作上下文是什么

Codex 来源适配器
→ 属于哪个 thread、AI 回了什么、调用了什么工具

ES
→ 哪个进程真正触碰了资源

FSEvents
→ 哪些文件变化

Git
→ 工程内容具体怎样变化
```

这些事实可以互相引用，但不能粗暴合并成一个“万能事实”。

原则：

> **严格材料，宽松关系。**

# 7. 第 0 层：确定性机器事实翻译

事实层之后、开放式 AI 之前，存在第 0 层。

它负责：

> **把底层系统事实翻译成可读现实，不解释意义。**

数据流：

```text
原始系统事件
↓
解析
↓
统一时间
↓
稳定身份映射
↓
确定关系闭合
↓
重复 / 心跳噪声归并
↓
自然语言事实翻译
↓
初始现实文档
```

允许使用：

```text
解析器
规则
字典
模板
确定性状态机
```

不使用开放式 AI 去猜确定事实。

允许压缩：

```text
纯重复事件
composition 中间态
确定属于同一次原子操作的低层事件
无意义心跳
```

禁止压缩掉：

```text
方案差异
结果差异
未知
失败
来源不一致
```

原则：

> **消除机器噪声，不消除现实差异；允许翻译，不允许增义。**

# 8. 第一条正式认知产品：个人叙事功能块

个人叙事不是生活日记。

当前定义：

> **个人叙事是一个人在世界中生活、思考、判断、行动并受到现实反馈之后，留下的自我认知具象痕迹。**

它回答的不是：

> 今天几点做了什么？

而是：

```text
我接触了什么
为什么在意
怎样理解
怎样行动
现实怎样回应
判断怎样变化
什么最终留在我身上
```

当前完整链：

```text
公共现实事实
↓
第 0 层初始现实文档
↓
个人叙事 AI 草稿
↓
人物日历 / 审核 UI
↓
用户批准 / 纠正 / 局部重写 / 拆分 / 合并
↓
用户确认正文
↓
SQLite 正式 personal_narrative revision 事务提交
↓
个人叙事功能块 END
```

详细局部规范：

`docs/spec/2026-08-06-DCF-个人叙事功能块实施规范.md`

---

## 8.1 个人叙事必须清晰，也必须保留未来差异

清晰不等于短。

详实不等于保留所有工具调用。

必须尽量保留：

```text
真正的问题
主要方案
重要操作结果
失败暴露的东西
成功里程碑
判断转折
能力 / 方法 / 认识变化
未吸收的问题
因已有积累而出现的新方向
```

原因不是“未来项目叙事可能用到”，而是：

> **这些差异本身构成个人认知。**

未来功能只是因此有机会重新发现它们。

---

## 8.2 审核不是数据库维护，而是认知生产

人物日历仍采用既定结构：

```text
日历
↓
某天 / 某叙事段
↓
交互轨迹
+
个人叙事草稿
+
来源引用
+
用户修改区
```

核心动作：

```text
批准
纠正
局部重写
拆分
合并
标记“这段没有什么值得保留”
回看来源
```

日历负责导航时间，不制造日记负担。

---

## 8.3 AI 原稿、审核记录与正式认知分离

必须区分：

```text
AI 原稿
→ 审核证据

用户修改差异
→ 审核证据

用户确认正文
→ 正式个人认知 revision
```

未经用户确认的 AI 原稿不得直接进入正式个人历史。

# 9. 锚定认知世界：SQLite 是长期认知权威

当前裁决：

> **SQLite 作为 DCF 长期认知对象与关系的权威持久层。**

这不是因为 SQLite 是“最强搜索数据库”，而是因为当前长期存储对象已经从原始 AI trace 收缩为高价值认知对象。

此前 storage-kernel 实验已经证明：对于巨大完整 trace，压缩自索引结构可以在空间、精确搜索和同步接缝上产生显著杠杆。

但当前 DCF 改变了问题本身：

```text
巨大原始语料
↓
现实提纯 + 个人叙事
↓
只把高价值认知对象进入长期认知世界
```

因此：

```text
存储规模问题
→ 被需求层大幅吸收

规模导致的性能问题
→ 同时大幅减弱

搜索准确度
→ 成为主要值得投入复杂度的方向
```

---

## 9.1 稳定对象 + 不可变修订

长期认知采用：

```text
认知对象
+
不可变修订
```

逻辑模型：

```text
对象 object_id
├─ kind
├─ current_revision_id
└─ 生命周期元数据

修订 revision_id
├─ object_id
├─ content
├─ created_at
├─ author_kind
├─ source_refs
└─ content_hash
```

修改正式认知时：

```text
旧 revision 保留
↓
新增 revision
↓
current_revision_id 前移
```

禁止原地覆盖旧正式正文。

---

## 9.2 稳定文本锚点

任何正式修订都可以通过：

```text
revision_id
+
start_offset
+
end_offset
```

形成稳定文本锚点。

以后：

```text
搜索结果
项目切片
Wiki 标注
知识标注
语言弹药标注
人工关系
```

优先指向锚点，而不是复制正文后产生第二份材料权威。

---

## 9.3 数据库保存认知，文件用于导出 / 交换

正式个人叙事不再要求 Markdown 文件作为长期权威。

原因：个人叙事天然需要：

```text
日历查询
时间范围查询
修订历史
多种重叠标注
多种切分
全文搜索
语义表示
关系查询
```

如果文件与数据库同时可写，就会额外制造同步系统。

当前原则：

> **数据库保存认知对象本身；Markdown / JSON / HTML 是导出、交换、阅读和备份格式。**

# 10. 查询诱导语义场：关系不提前存完，查询时重新生成

长期认知世界保存：

```text
认知原文
稳定修订
文本锚点
人工明确关系
```

它不试图提前保存未来所有可能关系：

```text
A 与 B 相似
A 支持 C
B 反驳 D
A 属于某个未来还不存在的概念
```

原因很简单：未来查询维度不可穷举。

当前采用：

> **查询诱导语义场。**

最朴素的中文解释：

> **用户每次提出一个问题，系统临时从这个问题的角度重新给历史材料打相关度分数；关系由当前问题生成，而不是要求十年前提前存好。**

详细局部规范：

`docs/spec/2026-08-06-DCF-锚定认知世界与查询求解公共能力规范.md`

---

## 10.1 语义场的职责

语义场回答：

> **在这一次问题下，哪些过去材料可能相关？**

它不回答：

> **这些材料组合起来一定成立吗？**

核心纪律：

> **语义场负责发现，不负责保证。**

> **语义负责寻找，锚点负责证明。**

所有高质量语义结果最终必须回到真实 `revision + span`。

---

## 10.2 可重算检索表示

围绕同一个正式认知世界，可以同时存在多套可删除表示：

```text
FTS5 词法表示
字符三元组表示
稠密语义向量
词元级多向量表示
滑动语义窗口
项目型视图
Wiki 型视图
知识型视图
未来新的表示
```

它们都不是事实权威。

模型升级时可以全量重算，而不修改正式认知历史。

---

## 10.3 当前准确度优先的搜索阶梯

个人规模是结构优势。

当前原则：

```text
搜索准确度
>
节省几十 / 几百 MB 索引空间
>
互联网级吞吐优化
```

当前搜索能力按真实查询集逐步晋级：

### 第一层：词法检索

```text
FTS5
+
中文分词
+
字符三元组
```

负责专有词、原话、路径、ID、短字符串。

### 第二层：稠密语义表示

文本映射成语义向量，按含义召回。

个人规模允许时：

> **优先精确全量比较，不先使用近似最近邻搜索。**

### 第三层：词元级后期交互

保留一段材料内部多个细粒度语义表示，让查询中的不同语义单位在查询时寻找各自响应最强的位置。

当前第一批实验候选：ColBERT / MaxSim 类路线。

### 第四层：联合阅读重排

把：

```text
当前问题
+
候选原文
```

同时交给强模型判断相关度，用于最终 Top-K 排序。

### 实验扩展：查询条件化评分器

允许 Hypencoder 一类“查询生成当前评分函数”的路线作为实验位，但不作为 P0 依赖。

---

## 10.4 多路召回与排名融合

不同检索器犯不同错误，因此不寻找“一种万能检索”。

首版公共形态：

```text
词法 Top-K
+
字符 Top-K
+
稠密语义 Top-K
+
其他视图 Top-K
↓
候选并集
↓
倒数排名融合（RRF）
↓
可选后期交互
↓
联合阅读重排
↓
真实锚点
```

具体 K、模型、融合常数、是否启用某一层，全部由真实 DCF 查询集决定。

---

## 10.5 查询关系默认临时存在

如果 2030 年的一次查询首次发现：

```text
2026 的材料 A
与
2028 的材料 B
可能体现同一种思考模式
```

默认只是本次查询关系。

只有用户或正式功能明确决定保存时，才新增：

```text
2030：当前认为 A 与 B 存在关系 R
```

禁止回写成：

```text
A 从 2026 年开始就拥有关系 R
```

这让：

> **关系可以晚于材料出现。**

# 11. 多种切分 / 标注：不是中央中间层，而是可替换语义视图

当前明确否决：

```text
个人叙事
↓
唯一标准自包含切分
↓
所有未来功能只能消费这一层
```

允许：

```text
同一 revision
├─ paragraph/v1
├─ semantic-window/v2
├─ project-view/v1
├─ project-view/v2
├─ wiki-view/v3
├─ knowledge-view/v1
└─ 未来任意视图
```

不同切法可以：

```text
重叠
包含
粒度不同
模型不同
版本不同
目标不同
```

它们只是：

> **某个 processor / model / rule 对正式认知世界建立的一套标注或检索视图。**

公共层不规定“什么是正确切法”。

原则：

> **源认知统一，切法不统一。**

> **不要建立中央语义本体。**

# 12. 未来认知功能：独立提出问题，重新取材

项目叙事、Wiki、知识卡、语言弹药等都不应该由个人叙事保存动作强制触发。

它们是独立功能块。

公共模式：

```text
功能提出自己的当前问题
↓
查询诱导语义场
↓
找到相关真实锚点
↓
功能内部 AI / 规则 / 算法处理
↓
形成本功能自己的正式结果
```

因此：

> **个人叙事负责形成高质量认知原件；未来意义由未来查询重新发现。**

---

## 12.1 项目叙事

项目叙事不是项目考古。

它主要回答：

> **这段项目经历最终给我留下了什么，并怎样把项目的可行动边界推进到今天？**

它关注：

```text
最初缺什么
经历了哪些关键探索
失败留下了什么
成功留下了什么
哪些成果进入下一阶段
目标怎样变化
当前已经具备什么
下一步为什么现在成为可能
```

原则：

> **项目是价值的生产现场，不是价值的永久住所。**

> **项目拥有关系，不拥有材料。**

项目功能通过查询引用个人叙事、正式文档、Git / GitHub 工程现实等材料，而不是把材料搬进项目私有仓库。

---

## 12.2 Wiki

Wiki 功能提出：

> **解释当前主题，需要哪些历史材料？**

然后动态取材、组织当前解释。

Wiki 可以拥有自己的正式页面、版本和视图，但不取得个人叙事原件所有权。

---

## 12.3 知识卡

知识卡功能提出：

> **过去有哪些材料共同支持一个可迁移原则 / 区分 / 方法？**

AI 归纳形成知识卡。

知识卡必须能够回到支持它的真实锚点。

---

## 12.4 语言弹药

语言弹药功能关注：

```text
高密度表达
稳定判断
可复用措辞
高维概念的短表达
```

它可以使用自己的切片视图和检索方法，不要求项目叙事 / Wiki 先生成。

---

# 13. 约束求解：开放世界发现之后的确定世界计算

查询诱导语义场与约束求解器不是替代关系。

它们处理两种不同未知：

```text
语义未知
→ 我甚至不知道过去哪些东西与当前问题有关
→ 查询诱导语义场

组合未知
→ 已经知道变量和规则，但不知道哪些组合成立
→ 约束求解器
```

完整链：

```text
自然语言问题
↓
查询诱导语义场找相关历史
↓
AI 理解 / 约束编译
↓
严格结构化约束包
↓
确定性求解器
↓
可行 / 冲突 / 最优
↓
AI 回译解释
↓
每个关键结论回到真实锚点
```

原则：

> **开放世界交给查询与 AI；封闭规则交给求解器。**

> **不要让不确定 LLM 做确定的事。**

---

## 13.1 约束编译器

求解器不能直接吃自然语言个人叙事。

必须经过“约束编译器”。

输出至少区分：

```text
实体 / 候选
决策变量
硬约束
软约束
目标函数
来源锚点
不确定项
```

硬约束来源允许包括：

```text
用户当前明确要求
系统确定事实
条件完全一致且明确适用的历史规则候选
```

禁止：

```text
“语义上看起来用户很在意离线”
↓
自动变成
必须离线 = true
```

AI 推断与模糊偏好只能进入：

```text
软约束
待确认项
候选解释
```

---

## 13.2 当前求解器候选

初版通用求解优先使用：

> **可满足性模理论求解（SMT），当前首选候选 Z3。**

适合：

```text
布尔条件
数值边界
蕴含
互斥
依赖
多目标优化
```

如果未来出现纯排程 / 指派等问题，可通过同一公共接口接入 CP-SAT 等专用求解器。

上层认知世界不得因此绑定单个求解器实现。

---

## 13.3 第一批真正值得求解的功能

优先：

```text
架构选择
项目涌现
```

而不是给所有功能强行加 Solver。

### 架构选择

```text
需求
↓
语义场找历史原则 / 失败 / 技术事实
↓
AI 编译硬约束 / 软约束 / 候选构件
↓
求解器排除非法组合、优化残差
↓
AI 解释为什么
```

### 项目涌现

```text
当前目标 / 缺口
↓
语义场找已有能力 / 成果 / 工具 / 失败经验 / 未满足需求
↓
约束编译
↓
求解器判断：
已经满足 / 还缺一个条件 / 存在硬冲突
↓
AI 生成候选项目解释
```

# 14. 搜索准确度与求解正确性必须成为长期评估资产

## 14.1 DCF 真实认知查询集

不能只用模型自造 benchmark。

必须积累用户真实会问的问题，例如：

```text
“之前哪里开始认为项目拥有关系而不拥有材料？”
“什么时候把复杂度吸收升格成架构判断标准？”
“有哪些案例是通过改变问题定义而不是增强技术来消掉复杂度？”
“哪个失败后来变成了另一个项目的能力？”
```

每条查询人工标注：

```text
强相关锚点
可接受相关锚点
明显误召回
```

核心指标：

```text
Top-1 命中
Recall@K
MRR
nDCG@K
锚点准确率
```

任何新的分词器、向量模型、切分视图、后期交互、融合算法和重排器必须跑同一查询集。

---

## 14.2 求解器确定性测试集

必须独立维护：

```text
可满足案例
不可满足案例
已知最优案例
互斥
依赖
数值边界
软约束冲突
```

必须保证：

```text
硬约束绝不因优化而被违反
无解正确返回无解
相同约束包重复求解一致
已知最优案例得到正确目标值
支持时返回最小冲突核心
```

AI 解释得漂亮不能替代求解正确性证据。

---

# 15. 行动世界：只有认知闭环成立以后才扩大现实控制

没有行动层，DCF 已经可以是完整认知基础设施。

行动层让它进一步成为：

> **能够利用过去积累持续改变现实的认知与执行系统。**

任务必须能回答：

> **为什么有这个任务？它正在缩小什么缺口？**

来源可以是：

```text
用户明确目标
能力缺口
区分缺口
项目未闭合问题
知识缺口
现实失败
项目涌现结果
架构求解结果
```

自动生成候选任务不等于已经获得执行授权。

---

## 15.1 控制平面与正式 Job

任何独立正式工作默认脱离最小控制平面执行。

控制平面只负责：

```text
创建 / 派发
状态推进
进度 / 结果 / 失败
取消 / 超时 / 重试
恢复位置
健康检查
保持 UI / 诊断可响应
```

判断标准：

> **如果某项工作意外变慢或失败，DCF 是否仍应该能控制其他工作？**

如果应该，它就不能把控制平面一起卡死。

---

## 15.2 Agent 执行结果必须重新进入现实

必须坚持：

```text
Agent 声称完成
≠
现实已经完成
```

正确闭环：

```text
任务
↓
行动
↓
现实副作用
↓
系统重新观察
↓
Git / 文件 / 来源 / ES 等证明结果
↓
新现实重新进入认知链
```

执行系统制造现实；认知系统解释现实意味着什么。

---

# 16. World / Becsy / ECS：先作为运行边界，后作为工业化优化

DCF 借用 Becsy 最先要的是 World。

World 负责：

```text
功能运行隔离
局部活动状态
公共资源接入
功能重载
```

长期认知正文、知识全文等仍然在持久层，不强行 ECS 化。

只有真实出现大量同质活动对象时，才利用 ECS：

```text
紧凑热状态
Query 批处理
资源分组
去重
缓存
批量执行
执行重排
减少上下文切换
```

原则：

> **World 从早期就可使用；ECS 工业化必须由真实 workload 证明。**

---

## 16.1 高级语义状态机

当某类 AI 工作逐渐成熟，应该把已经理解的路径下沉为：

> **高级语义状态机。**

它表达：

```text
当前语义阶段
已有证据
还缺什么
合法下一步
什么时候调用 AI
什么时候确定推进
什么时候必须升级
完成条件
```

遇到模型未覆盖情况时必须显式产生：

```text
残差
+
需要升级
```

禁止低自由度执行器自行扩大自由度并继续猜。

---

# 17. 成熟 Agent Runtime 与 DCF 自研执行层并存

路线未知、高认知、开放探索任务继续优先使用成熟 Agent Runtime。

成熟路径经过真实轨迹验证后，可以逐渐：

```text
观察稳定模式
↓
抽取执行模板
↓
形成高级语义状态机
↓
下沉到 DCF 执行核
↓
规模运行
↓
残差再次升级给高自由度 Agent
```

原则：

> **探索态可以很重，稳定态必须尽量薄。**

> **DCF 学习稳定工作方法，不复制第三方 Runtime 的全部内部实现。**

---

# 18. 伪热更新与功能增长

DCF 不追求复杂的进程内 HMR。

目标是：

> **用快速、确定、可恢复的重启实现接近热更新的用户体验。**

逻辑过程：

```text
功能块新增 / 修改
↓
保存必要恢复位置
↓
活动运行层干净退出
↓
launchd / 宿主快速重启
↓
重新发现功能
↓
重建 World Registry
↓
重建功能 / 动作注册
↓
重建 Surface Registry
↓
恢复长期状态与必要活动状态
```

目标行为：

> **新增一个功能，不需要人工修改主导航、侧边栏和悬浮球宿主代码才能出现。**

Swift 原生扩展最终采用 Bundle、动态库还是 helper 等属于局部实施门禁，不改变上述行为目标。

---

# 19. 当前施工总路线

以下是**当前真实施工顺序**，不是概念等级。

原则：

> **每个阶段都必须闭合一条真实用户纵向体验，不做“先把所有后端做完以后再补产品”。**

---

## P0 — 新 macOS 产品骨架与锚定数据库

目标：先建立所有后续功能都会复用的最薄骨架。

必须完成：

```text
独立 macOS App
完整形态 / 侧边栏 / 悬浮球 Host
功能注册 / Surface 注册
Bun 功能发现与伪热更新骨架
launchd + XPC 稳定运行接缝
SQLite 锚定认知数据库
对象 / 不可变修订 / 审核记录 / 来源引用基础模型
诊断入口
```

P0 不要求同时实现所有认知功能。

行为门禁：

1. 新增测试功能块不需要修改已有功能内部代码；
2. 新功能的完整形态 / 侧边栏 / 悬浮球贡献按声明自动出现；
3. 重载后 SQLite 正式状态不丢；
4. 某个功能 Job 卡死时宿主和其他功能仍可响应；
5. 数据库事务失败不会产生半个正式 revision；
6. Diagnostic 能说明当前加载的功能、World、数据库版本和恢复状态。

## P1 — 公共现实薄壳进入产品

注意：这一阶段是**实施既有实验裁决**，不是重新调查 macOS 能力。

```text
确定性事实
unknown / gap
```

P1 行为门禁：

- 重启 / 断线后能继续增量消费；
- 同一现实不会因为重复读取制造第二份事实；
- 来源能证明什么就只写什么；
- 不需要自建第二套全盘 watcher / session detector。

## P5 — 查询诱导语义场

```text

↓
```

每一层必须回答：

不为了“现代搜索栈看起来完整”引入模型。

## P6 — 第一批独立认知功能


```text

↓
```

禁止：


P6 的核心验收不是“生成了很多东西”，而是：

> **新增一个认知功能时，已有认知功能之间的接缝没有随之增长。**

## P7 — 语义发现 + 约束求解首个闭环

只选一个真实问题先闭合，优先：


```text

↓

↓

↓

↓

↓
可行 / 冲突 / 最优
↓
AI 回译
↓
关键结论可追到来源
```

P7 行为门禁：

- 不确定 AI 推断不得进入硬约束；
- 求解器不能直接读取自然语言并自行猜变量；
- 无解时必须诚实返回无解；
- 关键约束必须可追溯；
- 求解正确性由确定性测试集证明。

# 21. 当前明确冻结的架构裁决

以下不应被普通实现 AI 重新发散：

```text
主产品 = 独立 macOS App
三 Surface = 完整形态 / 侧边栏 / 悬浮球
功能块拥有能力，宿主拥有展示秩序
限制关系，不限制功能内部能力
macOS 公共现实底座采用既有实验裁决
第 0 层必须确定性、无增义
个人叙事是第一条正式认知产品闭环
正式个人叙事进入 SQLite
长期认知采用稳定对象 + 不可变修订
SQLite 是锚定认知世界权威
Markdown 是导出 / 交换，不是第二可写权威
搜索表示全部可重算
未来关系优先查询时生成，不提前穷举
不存在唯一标准切分层
不存在中央语义本体
项目拥有关系，不拥有材料
项目叙事 / Wiki / 知识卡 / 语言弹药是独立功能块
语义场负责发现，不负责保证
求解器负责确定组合，不负责开放发现
AI 推断不得偷偷升级成硬约束
个人规模优先换取搜索准确度，而不是互联网级吞吐
认知变化追加，不静默覆盖
Agent 自报成功不等于现实成功
World 是运行隔离，ECS 是按证据引入的优化
```

# 25. 自动验收总原则

> **锁定“现实里做成什么才算对”，不要锁死“代码必须怎么写”。**

至少维护以下反例门禁。

## 25.1 现实事实错误

```text
只观察到 URL 变化
→ 却记录成用户主动打开
→ 失败
```

## 25.2 第二事实权威

```text
macOS / Git 已经拥有确定现实
DCF 又维护第二套并发生漂移
→ 失败
```

## 25.3 AI 草稿污染正式认知

```text
AI 自动生成个人叙事
→ 未经用户确认直接进入正式 revision
→ 失败
```

## 25.4 历史覆写

```text
用户后来改了理解
→ 旧 revision 消失
→ 失败
```

## 25.5 搜索没有真实锚点

```text
系统只回答“你以前认为 X”
却无法返回真实 revision + span
→ 失败
```

## 25.6 查询关系被冒充成永久事实

```text
某次语义模型认为 A 与 B 有关
→ 自动写回 A 的历史属性
→ 失败
```

## 25.7 下游强耦合

```text
新增 Wiki 功能
→ 必须修改个人叙事和项目叙事内部逻辑
→ 失败
```

## 25.8 搜索投影阻塞认知保存

```text
embedding 服务故障
→ 用户不能保存正式个人叙事
→ 失败
```

## 25.9 求解器输入污染

```text
AI 模糊推断
→ 自动变成硬约束
→ 失败
```

## 25.10 求解器被 AI 假冒

```text
AI 直接说“所有约束都满足”
却没有确定求解记录
→ 失败
```

## 25.11 Surface 双状态

```text
完整形态修改对象
侧边栏仍显示另一份独立业务状态
→ 失败
```

## 25.12 控制平面失活

```text
一个正式 Job 卡死
→ DCF 无法查询 / 取消其他 Job
→ 失败
```

## 25.13 Agent 自报冒充现实

```text
Agent 声称文件已经修改
实际 Git / 文件 / Effect 证据不存在
系统仍宣布成功
→ 失败
```

# 26. 当前成功标准

当前 DCF 不以“功能数量”作为阶段成功标准。

真正成功顺序是：

```text
1. 现实能够可靠进入
2. 现实能被确定性翻译
3. 用户能够低成本形成并确认个人叙事
4. 正式认知可以跨时间保持历史
5. 未来新问题能够从旧认知中找到真正相关材料
6. 新功能可以独立利用这些材料而不扩大旧功能接缝
7. 明确条件可以进入确定求解而不是继续让 AI 猜
8. 认知能够安全地产生行动
9. 行动结果重新进入现实与认知循环
10. 只有真实规模出现以后才工业化
```

# 28. 一句话总结

> **DCF 当前路线是：让 macOS、来源系统和 Git 尽量拥有现实；用确定性的第 0 层把现实翻译成可读材料；以“个人叙事”作为第一条正式认知产品，让 AI 起草、用户校准，并把用户确认后的认知以 SQLite 的稳定对象 + 不可变修订长期锚定。之后不提前穷举未来所有分类、切分和关系，而是在查询发生时通过多套可重算语义表示形成“查询诱导语义场”，让项目叙事、Wiki、知识卡和未来功能都能独立重新取材；当问题从开放发现进入明确变量、规则和组合判断时，再由 AI 约束编译器把材料转换成可追溯约束，交给 SMT / Z3 等确定性求解器。所有功能通过同一个功能块 / World / Surface 机制接入独立 macOS App，新增功能不要求旧功能理解它；只有在认知闭环、查询准确度和确定求解都成立以后，DCF 才进一步把结果转成任务和 Agent 行动，并要求现实结果重新进入证据与认知循环。整个系统始终坚持：系统拥有现实、DCF 拥有认知；语义负责寻找、锚点负责证明；开放世界交给查询与 AI、封闭规则交给求解器；认知变化只追加、不静默覆写；功能可以增长，但接缝不能跟着增长。**
