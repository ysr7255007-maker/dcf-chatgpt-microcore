# DCF 个人叙事功能块实施规范

日期：2026-08-06  
状态：当前功能块实施规范  
适用范围：从 macOS / 来源系统已经存在的现实事实进入 DCF，到用户审核后的正式个人叙事文件原子落盘为止。

> 本规范不重新研究 macOS 公共能力，不重新设计 DCF Surface，也不定义任何下游切分、项目叙事、Wiki、知识卡或语言弹药规则。

# 1. 个人叙事的当前定义

个人叙事不是生活日记，也不是工作日报、项目周报或操作流水。

个人叙事是：

> **一个人在世界中生活、思考、判断、行动并受到现实反馈之后，留下的自我认知具象痕迹。**

它记录的不只是“世界发生了什么”，而是：

```text
我接触了什么
↓
我为什么在意
↓
我怎样理解
↓
我怎样行动
↓
现实怎样回应
↓
我的判断怎样变化
↓
哪些东西最终留在我身上
```

个人叙事首先服务于本人重新理解自己。

它必须具备独立阅读和审核价值：用户回看它时，应能重新理清思路、发现误解、看见转折，并可能获得新的关联或灵感。

因此：

> **用户审核不是替 DCF 维护数据库，而是一次真实的自我认知生产。**

个人叙事同时必须保留足够细节，使未来其他独立功能块仍有机会从中重新判断价值；但本功能块不为任何具体下游功能预先定制材料结构。

# 2. 既定总体架构：系统拥有现实，DCF 拥有认知

本功能块不得重新制造 macOS 已经长期维护的现实世界。

当前事实所有权已经裁决为：

```text
文件变化历史
→ macOS FSEvents / .fseventsd 拥有

当前文件索引
→ macOS Spotlight 拥有

前台活动与屏幕活动分段
→ macOS KnowledgeC / CoreDuet + NSWorkspace 拥有

用户最终提交文本
→ macOS IMK + Unified Logging Persist 拥有现实记录

进程 / 文件机器动作收据
→ macOS Endpoint Security / eslogger 提供

进程生命周期
→ launchd + XPC 拥有

认知关系 / 当时理解 / 后来理解 / 用户校准
→ DCF 拥有
```

DCF 不复制第二份同义权威。

个人叙事功能块只读取 DCF 公共事实层已经提纯、带来源锚点的现实增量。

# 3. 既定 macOS 公共现实底座

以下不再作为候选重新讨论，而作为当前正式事实底座继承。

## 3.1 文件现实层

```text
FSEvents + Spotlight
```

负责：

- 从持久 event id 取得文件变化历史；
- 通过 Spotlight / MDQuery / mdls 查询当前文件世界；
- 删除 DCF 自建全盘 watcher、定期全量扫描、重复文件索引与事件队列持久化。

个人叙事功能块消费提纯后的重要文件现实，不直接维护自己的文件 watcher。

## 3.2 活动时间骨架

```text
KnowledgeC / CoreDuet + NSWorkspace
```

负责：

- 前台 App 起止分段；
- 屏幕亮灭 / 使用分段；
- 实时 App 生命周期和前台变化；
- 删除 DCF 自建 session detector 和第二套前台活动历史。

这层只提供活动时间背景，不提供项目、目标、意图或因果解释。

## 3.3 用户表达事实层

```text
IMK + Unified Logging
private-data + Persist=Debug
```

已实测能够提供：

- 最终 `insertText` 明文；
- composition 中间态；
- 语音提交；
- 客户端 bundle id 归因；
- Persist=Debug 后的掉线补读。

因此基础文字事实不再依赖键盘监听、AX 文本抓取或 OCR 输入还原。

## 3.4 机器 Effect 收据

```text
Endpoint Security / eslogger NOTIFY 精简管道
```

当前用于：

```text
exec
create
rename
exit
```

它提供独立于 Agent 自报结果的物理现实收据。

Agent Runtime 不要求主动向个人叙事功能块汇报“我做了什么”。

DCF 可以基于 pid / ppid / exec 命令行尽力关联现实 Effect，但未知关联必须保持未知。

## 3.5 生命周期

```text
launchd + XPC
```

负责常驻观察壳和相关进程生命周期，不由个人叙事功能块自建 supervisor。

## 3.6 来源专用高语义事实

IDE / Agent 本地数据库、结构化事件流、聊天来源记录等继续允许作为来源专用增强事实源。

它们信息密度高，但不取得公共现实底座身份。

## 3.7 已降级 / 淘汰事实面

不得重新提升为基础现实面：

```text
屏幕 / OCR 全量观察
DCF 自建全盘 watcher / index
DCF 自建 session detector
每个 Agent 一套结果自报事实链
```

AX 保留为来源专用、机会主义的结构化 UI 增益，不承担基础兜底身份。

# 4. DCF 常驻观察壳与个人叙事的关系

当前公共现实结构已经裁决为极薄观察壳：

```text
launchd 托管的 DCF 常驻观察壳
├─ FSEvents stream（游标消费）
├─ eslogger NOTIFY 精简集管道
├─ IMK / Unified Log 明文消费者与游标补读
└─ KnowledgeC 分钟级轮询
```

观察壳负责把系统现实提纯后进入 DCF 持久层。

个人叙事功能块不得：

- 再起一套 FSEvents watcher；
- 再做一套前台 App session detector；
- 再全量消费 Unified Log；
- 再为 Codex / OpenCode / shell 分别维护执行结果观察器。

它只消费公共层已经存在的现实事实。

---

# 5. 第 0 层：机器事实翻译

在开放式 AI 形成个人叙事之前，必须存在一个确定性的第 0 层。

其职责不是理解人生、项目或价值，而是：

> **把底层事实语言翻译成可直接阅读、可直接审核、同时不增义的现实文档。**

数据流：

```text
提纯系统事实
↓
确定性主体 / 对象 / 时间绑定
↓
规则与字典翻译
↓
确定性去噪与归并
↓
第 0 层初始现实文档
```

第 0 层优先使用：

```text
解析器
规则
字典
模板
确定性状态机
原生系统身份
```

不使用开放式 AI 来猜测确定事实。

---

# 6. 第 0 层的主体归因硬规则

必须严格区分：

```text
系统观察到状态变化
≠
证明用户主动造成该变化
```

例如事实只证明：

```text
Chrome 当前标签页 URL：A → B
```

第 0 层只能写：

> Google Chrome 当前标签页 URL 从 A 变为 B。

禁止写：

> 用户打开了 B。

同理：

```text
前台应用：Chrome → Codex
```

只能写：

> 前台应用从 Google Chrome 变为 Codex。

禁止在第 0 层写：

> 用户切到 Codex 继续开发 DCF。

只有事实源明确证明主体、动作和对象时，才能自然语言展开对应关系。

第 0 层禁止自行生成：

```text
项目归属
用户目标
行为目的
因果
采纳关系
重要性
长期价值
```

---

# 7. 第 0 层的翻译与压缩纪律

允许的确定性处理：

- 统一时间；
- bundle id / process id / native id 映射为稳定可读名称；
- 明确的 parent-child / call-result / file-effect 原生关系闭合；
- composition 中间态合并为可辨认的最终提交过程；
- 重复心跳和纯系统噪声删除；
- 同一次确定操作产生的低层重复事件归并；
- 将外部英文协议术语映射为 DCF 内部稳定中文表达。

禁止：

- 为了顺畅而补出事实源没有证明的主语；
- 把时间相邻解释成因果；
- 把路径解释成项目；
- 把前台 App 解释成用户目标；
- 把 Agent 自报成功解释成现实成功；
- 把“没有观察到”解释成“没有发生”。

原则：

> **消除机器噪声，不消除现实差异；允许翻译，不允许增义。**

---

# 8. 第 0 层输出：初始现实文档

第 0 层输出一个普通、可读、可追溯的初始现实文档。

它的目的有三项：

1. 给个人叙事 AI 一个远比底层事件更干净的输入；
2. 给用户在审核个人叙事时提供回忆锚点；
3. 当叙事出错时区分“事实源错 / 第 0 层翻译错 / AI 理解错”。

文档以时间与已经确定的活动分段为骨架。

允许示意：

```text
2026-08-06

05:12–05:38
前台应用：ChatGPT
文本客户端最终提交：……
……

05:39–06:02
前台应用：Codex
Codex / shell 相关现实 Effect：……
文件变化：……
……
```

它不是日记，也不是个人叙事，只是机器能够证明的现实的人类可读版本。

初始现实文档不是长期认知权威，可以随第 0 层规则升级重新生成。

---

# 9. 个人叙事 AI 的输入与职责

个人叙事 AI 读取：

```text
当前复盘时间范围的初始现实文档
+
必要的来源引用
+
必要的前后连续背景
+
个人叙事写作约束
```

它可以进行开放式综合理解。

目标不是逐条复述现实，而是把现实恢复成一个人可以重新理解的认知轨迹。

个人叙事应优先组织：

```text
当时主要关注什么
↓
为什么值得处理
↓
采用了什么主要思路或操作
↓
现实怎样回应
↓
哪里发生关键转折
↓
判断怎样改变
↓
最后留下了什么
↓
当时 / 当前怎样理解这段经历
```

时间是坐标，不是正文的主要结构。

禁止默认生成“早上 / 中午 / 晚上做了什么”的生活日记。

---

# 10. 个人叙事的“清晰 + 详实”要求

清晰不等于短。

详实不等于保留所有操作。

本规范定义：

> **清晰 = 用户无需重新拼接大量原始上下文，就能理解主要对象、思路和转折。**

> **详实 = 未来可能改变理解和行动的关键差异没有被摘要掉。**

允许压缩：

- 重复操作；
- 无意义等待；
- 工具调用流水；
- 没有后果的小动作；
- 已被后续结果完全吸收的低层细节。

必须尽量保留：

- 当时真正试图解决的问题；
- 主要方案；
- 重要操作结果；
- 失败及失败暴露的东西；
- 成功中间里程碑；
- 判断发生变化的原因；
- 得到的成果、能力、方法或认识；
- 尚未吸收的问题；
- 因已有积累而变得可能的新方向。

这些内容首先因为它们构成个人认知而保留，而不是为了预先服务项目、Wiki 或知识卡。

---

# 11. 既定人物叙事 Surface：日历入口

人物叙事继续沿用既有“人物日历”设计，不重新发明入口。

日历负责提供天然时间坐标。

它不代表：

```text
每天必须有内容
每天必须审核
每天必须形成完整日记
```

允许：

- 某天完全空白；
- 某天只有少量现实；
- 连续几天形成一个叙事段；
- 几周后再补审；
- 只审核重要日期。

核心原则：

> **日历负责导航时间，不制造日记负担。**

日历单元应显示已有状态，但状态服务导航而非制造任务压力。

---

# 12. 既定当天 / 叙事段审核页

点击日期或叙事段后，继续沿用既有结构：

```text
Interaction Trajectory
+
Human Narrative Draft
+
来源交互引用
+
用户修改区
```

其中语义更新为：

```text
Interaction Trajectory
→ 第 0 层初始现实文档及其可展开现实轨迹

Human Narrative Draft
→ 个人叙事 AI 草稿

来源交互引用
→ 支撑当前现实稿和叙事的原始事实 / 来源锚点

用户修改区
→ 对叙事的真实校准与复盘
```

页面主要动作继续是：

```text
批准
纠正
局部重写
拆分
合并
标记“这段没有什么值得保留”
回看来源
```

人物叙事页不得塞入项目管理、知识卡管理、Wiki 管理或下游切分操作。

核心原则：

> **人物叙事页面的主要动作是校准，不是管理项目。**

---

# 13. AI 原稿、用户修正版与修改差异

既定 UI 要求继续保留：

```text
AI 原稿
用户修正版
修改差异
```

用户审核不是简单把 AI 原稿覆盖成最终文本。

系统至少必须能够回答：

```text
AI 最初怎样理解
用户最终怎样修改
二者哪里发生差异
```

修改差异本身是重要的认知校准材料。

但本功能块的最终产品仍然是用户修正版个人叙事文件；差异历史如何被未来其他功能消费，不属于本规范。

---

# 14. “当时理解”与“审核时新理解”必须区分

用户审核时可能发生两类动作：

## 14.1 修正 AI 对当时经历的表达

例如：

> AI 把当时的主要不满写成“效率”，用户修正为“接缝残差”。

这是对草稿的校准。

## 14.2 审核过程中产生新的理解

例如：

> 回看以后才意识到几个以前分散的问题实际上属于同一条长期路线。

这个理解形成在审核时，不能静默伪装成“当时已经知道”。

因此用户修正版文件必须能够在正文中保留时间差异，例如通过自然语言段落、时间标记或明确的后补说明表达：

```text
当时：……

复盘时进一步意识到：……
```

本规范不冻结具体 Markdown 标记语法，但实施必须保证语义不被回写抹平。

---

# 15. 个人叙事文件是本功能块唯一正式输出

用户完成审核后，系统生成一个普通文件工件。

推荐载体：Markdown。

文件内容必须首先适合人直接打开阅读。

机器元数据保持极薄，只用于身份、时间与来源锚点，不把个人叙事变成数据库转储。

至少需要稳定表达：

```text
工件身份
叙事覆盖时间范围
形成 / 保存时间
来源现实文档或来源锚点
正文
```

具体字段名和 Front Matter Schema 不在本规范冻结。

---

# 16. 文件位置与身份

个人叙事按人类可理解的日期结构落盘。

例如：

```text
YYYY/
└─ MM/
   └─ DD/
      └─ 个人叙事相关文件
```

具体文件名不在本规范锁死。

硬约束：

> **物理路径服务人类组织，稳定工件身份服务机器关系。**

移动文件不得等于创建新的认知身份。

---

# 17. 保存语义

保存必须满足：

```text
用户完成审核
↓
生成完整文件内容
↓
写入临时位置
↓
校验完整性
↓
原子提交 / rename
↓
正式 personal-narrative 工件出现
↓
END
```

其他功能只能看到已经完整提交的工件，不得读到半写状态。

个人叙事功能块禁止在保存后主动：

```text
调用切分器
刷新项目
生成 Wiki
生成知识卡
生成语言弹药
触发项目推荐
```

它只完成一个现实结果：

> **Artifact World 中多出了一份正式个人叙事文件。**

谁以后读取它，由其他独立功能块自行决定。

---

# 18. 完整形态 / 侧边栏 / 悬浮球的既定 Surface 关系

本功能块遵守总实施规范已确定的 Surface 原则：

```text
功能身份 / 业务事实 / 动作语义只有一份
↓
完整形态 / 侧边栏 / 悬浮球只是同一功能的不同投影
```

不得为不同 Surface 复制第二套个人叙事状态或第二套审核逻辑。

## 18.1 完整形态

承载完整人物日历、Interaction Trajectory、Human Narrative Draft、来源引用、修改差异和正式审核动作。

## 18.2 侧边栏

只贡献适合高频窄空间使用的“待审核人物叙事 / 当前待校准叙事”入口或摘要，不复制完整编辑器和历史管理。

## 18.3 悬浮球

继续服从总产品原则：只允许极少量真正值得持续存在的状态或快捷入口。

个人叙事不因为存在未审核内容就默认制造持续红点、数量压力或日记债务。

具体侧边栏与悬浮球排序、组合、手势由宿主既有动态 Surface 编排负责，不在本功能块重写。

# 19. 诊断边界

普通人物叙事 UI 服务理解和校准。

工程事实进入 Diagnostic，而不是污染主界面。

诊断至少应能够追踪：

```text
本轮现实文档使用了哪些公共事实源
各来源游标 / 时间范围
哪些事实缺失或 unknown
第 0 层翻译规则 / 版本
个人叙事模型 / Prompt 版本
AI 原稿
用户修正版
修改差异
最终文件工件身份与路径
```

错误必须能够区分为：

```text
事实源没有观察到
事实提纯 / 第 0 层翻译错误
个人叙事 AI 理解错误
用户后来产生了新的理解
```

不得把四种问题混成“AI 写得不对”。

以下不是“遗漏”，而是有意留给独立功能块和真实材料后续演化：

```text

统一认知材料 Schema
项目材料怎么切

功能之间的强制联动
```

# 21. 实施步骤

按现有能力直接实施，不重新进入底层调研或 UI 头脑风暴。

## Step 1 — 复用公共现实底座

接入当前 DCF 持久层已经提纯的：

```text
FSEvents / Spotlight 文件事实
KnowledgeC / NSWorkspace 活动骨架
IMK + ULog 用户表达事实
ES / eslogger Effect 收据
来源专用高语义事实
```

不得复制对应观察机制。

## Step 2 — 实现第 0 层事实翻译

把提纯事实翻译为无增义的初始现实文档。

优先完成：

```text
主体归因纪律
稳定身份映射
重复事件归并
时间 / 活动段组织
来源锚点保留
```

## Step 3 — 接入个人叙事 AI

让 AI 只读取第 0 层现实文档与必要来源背景，生成详细、清晰、保留认知转折的个人叙事草稿。

## Step 4 — 接入既有人物日历与审核 UI

沿用：

```text
日历入口
Interaction Trajectory
Human Narrative Draft
来源交互引用
用户修改区
批准 / 纠正 / 局部重写 / 拆分 / 合并
```

并保留 AI 原稿 / 用户修正版 / 修改差异。

## Step 5 — 原子保存正式个人叙事文件

保存成功后立即结束功能块流程。

不做任何下游功能调用。

# 22. 行为验收

## A. macOS 公共能力没有被重复实现

若实现额外创建：

```text
第二套全盘 watcher
第二套前台 session detector
全量 ULog 同步器
每 Agent 一套结果观察器
```

立即判定违反规范。

## B. 第 0 层无增义

给定只证明“Chrome URL 变化”的现实，若第 0 层输出“用户打开该页面”，判失败。

给定只证明“前台 App 变化”的现实，若第 0 层自动生成项目目的，判失败。

## C. 个人叙事不是日记

真实一天材料中包含多次思考与操作时，输出必须能够重建主要问题、探索、反馈、转折和理解变化，而不是按小时流水罗列。

## D. 个人叙事不是操作日志

大量低价值工具调用不得机械进入叙事正文。

## E. 关键差异没有被压掉

真实材料中明确存在的重要：

```text
方案变化
判断转折
失败所得
成功里程碑
能力 / 方法 / 认识变化
```

在个人叙事中不得因为追求简洁而系统性消失。

## F. 审核本身有认知价值

用户无需重新打开大量原始材料，就能够借审核页重新理清主要过程，并有空间直接纠正或补充新理解。

## G. 当时理解与后来理解不混淆

审核时产生的新理解不得静默回写成过去已经具有的认识。

## H. UI 复用既定结构

实现不得另起一套与人物日历 / Interaction Trajectory / Human Narrative Draft 相冲突的独立产品界面。

## I. 功能块结束边界正确

用户修正版个人叙事文件原子保存后，本功能块必须结束。

即使系统完全没有：

```text
切分器
项目叙事
Wiki
知识卡
语言弹药
```

个人叙事功能仍必须完整成立。

---

# 23. 最高原则

> **系统尽量拥有现实，DCF 自己拥有认知。**

> **macOS 已经维护的现实，不由 DCF 再造第二份权威。**

> **第 0 层负责把事实语言翻译成人能读的现实，不替用户解释意义。**

> **个人叙事不是生活日记，而是自我认知的具象体现，是一个人在世界中生活后留下的具体认知痕迹。**

> **个人叙事要清晰直观，也要记述详实；可以压缩操作噪声，不能压断认知链。**

> **用户审核不是数据库维护，而是重新理解自己并继续产生认知的过程。**

> **个人叙事功能块的终点只有一个：形成用户修正版个人叙事文件并保存。**

> **文件保存以后，切分、项目叙事、Wiki、知识卡、语言弹药及任何其他解释方式全部属于独立功能块。**
