## 当前权威顺序

1. `2026-08-07-DCF-Capability-Registry-v1与能力发现收口规范.md`
   - 当前 Capability（能力）发现与登记最高权威；

   - 冻结产品主权判断、原生 / 涌现能力同级、ECS / World / Bun 三条复杂度切线与“四刀净化”方法；
   - 冻结 Capability Registry v1：15 项进入定型，`现实闭环行动` 状态为 `DISCOVERY_DEFERRED`；
   - 冻结三种交互能力名称：`全景沉浸交互`、`嵌入式交互`、`环境微交互`；旧“主页 / 侧边栏 / 悬浮球”降级为 Surface（界面载体）。
2. `2026-08-07-DCF-Capability与公共设施当前规范.md`
   - 当前公共设施、Provider（提供者）、Shared Semantic Component（共享语义组件）、ExternalOperation（外部操作）与 World Composition（World 组合）的高层架构权威；
   - 冻结 E0–E5 已验证的公共设施结构；
   - 其中旧 Capability 候选池、旧“继续 Discovery”与旧界面候选名称，已被第 1 项收口规范替代。
3. `2026-08-07-DCF-证据采集与多源证据编译增量规范.md`
   - `证据源采集管理` 与 `多源证据编译` 的最新专项边界；
   - 明确采集侧负责输入复杂度、编译侧负责输出复杂度；
   - 明确来源输出优先采用 ECS（实体组件系统）小组件自由组合，多源证据编译通过公共语义组件声明匹配，而不是依赖具体来源私有接口；
   - 记录声明匹配继续吸收路由、工作流、UI 贡献、诊断与恢复发现等接缝的架构推论；
   - 其中旧“能力主页 / 上下文侧边栏 / 环境悬浮球”称呼按第 1 项解释为历史 Surface 名称。
4. `2026-08-06-DCF-功能包络与施工控制规范.md`
   - 当前施工控制规范；
   - 已同步为：Registry 身份与 Envelope（能力包络）施工状态分离；
   - Capability Discovery 已收口，下一步从 15 项已登记能力逐项关闭 Envelope；
