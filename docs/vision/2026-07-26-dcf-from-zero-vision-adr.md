# DCF 从零愿景 ADR

- 状态：当前有效，随后续明确修正持续演化
- 建立日期：2026-07-26
- 范围：本轮从零生长的 DCF。旧 DCF 的架构、模块与既有结论不构成本轮愿景的预设前提；用户过去的生活材料仍可在保留来路的前提下重新进入

## 当前有效愿景

“DCF”目前只是暂定名称。

### 上位秩序

DCF 只在用户授权的生活边界内保存现实。任何 AI 都只能以这些现实为依据，形成带着来路的理解、建议或实现候选；候选不会因为材料已经成熟、代码已经生成或某层测试已经通过，就自动成为用户立场、当前成果或已经获得行动权的能力。用户拥有目标、观察边界、价值取舍和最终接纳权；DCF 保存对象身份、来路、边界、状态与证据，使变化可以被理解、验证、撤回和继续，却不替任何参与者越权判断。

这条秩序让不同职业朋友面对同一条变化链，而不是各自建立一套真相。全栈工程师形成具有确定身份的实现候选；UI 操作者保存用户实际看见和经历的现场；QA 证明某项承诺在具体实现与条件下是否成立；故障诊断工程师通过干预检验因果关系；代码审查员说明变化对权威、边界和未来替换能力的影响。用户最后决定是否接受这项变化进入当前生活，任何一层都不能拿自己的证据替下一层宣布成功。

同一项变化或故障始终共享同一个身份、候选、环境与隐私边界。界面现场、QA 证据、诊断实验和审查判断是围绕它展开的不同观察与证明层，不是几份彼此竞争的权威记录；后来的实验可以从原现场分叉，却不能反过来改写已经发生过的现实。

### 授权现实与材料库

系统的第一项功能，是在用户授权的生活边界内自动记录用户与所有 AI 的对话。在用户没有主动排除时，记录范围不因 AI 位于本地或网页端而改变，也不因对话属于闲聊或任务而改变。

这些对话将被归档，成为用户与 AI 共同产生的材料库。

观察与保存有清楚的层次。“不读取”意味着完全不观察，连短暂的界面余像也不会产生；“只用于当前、不归档”允许在当前话题中短暂处理，话题结束后不进入长期材料；“允许归档”才让现场进入材料库，并把原有边界传给后续衍生产物。用户主动排除的范围不是记录缺口，只有本应被记录却因中断或故障未能收回的部分才是缺口。

材料库同时保留两种东西：一层是完整、可追溯的原始对话，带着时间、来源和当时的连续上下文；另一层是可以随着后来理解不断重组的话题、片段和关系。后续形成的摘要、卡片、记忆和 Wiki 都能追溯回原始现场，却不能覆盖或冒充原件。第一次整理即使理解错了，也只需要重做上层组织，不会伤到已经发生过的历史。

全量归档不等于全量认同。材料库始终保留是谁说的、当时处于什么语境、用户是否接受、后来有没有修正，以及现实执行给出了什么证据。AI 提出的主张、用户正在试探的念头、已经明确形成的判断和经过现实验证的事实，不会因为被写进同一个对话就混成同一种“用户记忆”。一段随口探索可以被完整保存，却不会因此被固化为用户立场、长期设定、推荐或任务。

对话现场还包括真正参与过这次讨论的附件、网页、代码版本、任务结果和工具输出。DCF 会为它们保留当时可重新定位的关联，而不是只存下一句几年后已经失去所指的“看这个文件”。原始对象无法长期保存时，材料库也会留下足够理解其作用的快照或证据。

“授权范围内的全部对话已经收回”本身必须是可见事实。DCF 会持续知道哪些来源正在正常记录、哪里出现了中断、哪些时间段仍有缺口，并在能够恢复时自动补齐。无法证明完整的部分明确保留为缺口，不会用一次成功同步冒充那段生活已经被完整保存。

### 材料代谢、成果所有权与可迁移性

材料库并不止于保存。系统会定期派出 AI 梳理已经积累的对话，把跨时间、跨平台出现的相近话题重新聚在一起，并根据内容的性质持续形成不同用途的产物，包括可供用户直接阅读的 Wiki 仓库、记忆、知识卡，以及可被 AI 调用的 MCP 插件等。

新对话日常增量进入材料库，AI 则按照材料积累和关系变化定期回看，而不是要求用户维护一张梳理日程表。近期材料会被及时消化；旧材料在出现新联系、旧理解受到修正或某个方向重新活跃时也会被重新翻出。

这套消化有快慢两种节奏。正在发生的对话会及时形成继续当前事情所需的临时脉络；跨话题关系、长期观点和能力则在材料积累到足以改变理解时再做更深的重组。DCF 不会为了追求“实时更新”而把用户每一句临时情绪、玩笑或脑洞立刻加工成长期画像，也不会等到某次大型整理才让刚刚形成的重要决定失去作用。

这些整理产物既服务于用户观看，也服务于 AI 检索和继续工作。Wiki、记忆、知识卡和 MCP 插件不是必须依次经过的加工流水线，而是同一批材料针对不同用途长出的可读、可找、可调用形态。一个观点可以直接进入 Wiki，也可能在反复验证后成为卡片或可执行能力；每种产物都沿着自己的成熟程度继续变化。

所有整理产物都保留自己的来路、适用语境和演化关系，同时逐项声明谁拥有当前正文。材料库拥有原始现场、来源和演化关系；由材料库直接维护的视图可以随新材料重算；已经导出、允许用户直接编辑的成果则由对应文件拥有当前正文，DCF 只能为它形成修订候选，不能凭一次重新计算覆盖用户的修改。后来形成的新判断可以在被接纳后成为当前默认，旧判断仍留在历史位置并记录为什么被修改，不让互相冲突的版本同时冒充“最新”。

用户在任何一次对话中明确纠正 DCF，或直接修改一项成果，都会形成新的演化事实。相关 Wiki、记忆、卡片和任务理解据此生成带来路的联动修订，并按照各自产物声明的权威进入当前；修订可以撤销，原始现场始终不被改写。

当一个话题暂时中断时，DCF 还会保存当时真正的认知位置：已经想通了什么、仍卡在哪里、哪些假设没有验证、下一步为何尚未发生。它不是额外要求用户写一份交接，而是从当时的连续现场中留下一个可恢复的“续接点”。几天或几个月后再回到同一话题，用户首先拿回的是当时那颗还没想完的脑子，而不是一摞需要重新阅读的聊天记录。

其中一部分经过反复讨论、已经具有独立使用价值的内容，会继续凝结为可直接调取的卡片，例如用户与 AI 长期形成的对话设定、独特而锋利的观点，以及已经稳定的工作流程。它们可以同步到用户指定的 GitHub 私人仓库，由 DCF 主动拉取，因而不被某个对话窗口、某种 AI 或某台设备独占。对于这些允许用户直接编辑的成果，GitHub 文件拥有当前正文，材料库负责保存它为什么成为这样以及后来怎样变化；新材料只会产生可审查的修订候选，用户在 GitHub 的修改则作为新的事实重新进入演化来路。

GitHub 私人仓库承载的是用户能够直接阅读、修改、迁移和重新装填的成果，而不是某个 DCF 实现才能理解的不透明缓存。即使日后更换侧边栏、模型或整套实现，原始材料与已经形成的成果仍然可以被重新索引和生长；用户不会因为积累得越多，反而越难离开当前工具。

当某段知识进一步长成 MCP 插件或其他可执行能力时，“已经生成”不等于“已经获得行动权”。它必须先说明自己会做什么、需要接触什么、如何证明可用，并经过验证与用户确认后才进入可调用的工具架。DCF 会保存上一份实现、当时的适用条件、证据与撤回路径；这些前提仍成立时可以退回旧实现，前提已经被环境变化触及时则明确进入“需要复验”或“当前未知”，不会拿历史可信冒充今天仍然可用。材料库中的文字也不会因为某个插件失效而一起失去。

### 显性界面、边界继承与跨 AI 协作

DCF 不以“无感地在后台做好一切”为理想形态。它是用户看得见、随手够得着的左膀右臂，拥有自己的显性界面。界面的一种核心形态是当前对话旁的卡片侧边栏：它把已经提炼出的锋利观点和常用能力摆到手边，用户可以直接点击发射，让它进入正在发生的对话。

卡片虽然共享同一种界面形态，却可以承担不同动作：观点卡把已经磨利的判断直接送进对话，设定卡把长期形成的相处方式交给当前 AI，流程卡则可以启动一套已经稳定的工作。点击现成卡片默认直接发射，不再增加一层确认；DCF 只做目标环境所需的格式适配，不擅自改写卡片的核心内容。

这套侧边栏不从属于某个网页、某种 AI 客户端或某一类工作场景。网页 AI、本地 AI 和 IDE 中的 AI 工具都在它的支持范围内。用户把注意力切换到哪个窗口，DCF 就自动读取当前正在关注的界面，辨认此刻面对的是哪种 AI，并切换到对应的读取、发送和结果解析工具。用户不需要先告诉 DCF “现在要操作 ChatGPT”或“这次改用本地 Agent”，也不需要因为换了 AI 而重新寻找另一套入口。

当前获得焦点的窗口决定侧边栏此刻面向哪个 AI；已经开始的读取、发送或执行仍然绑定原来的会话，不会因为用户中途切换窗口就把结果送错地方。用户也可以随时改变某个窗口的观察与归档边界，侧边栏会明确显示当前是“不读取”“只用于当前”还是“允许归档”。其中“不读取”会立即停止观察，不会在用户看不见的地方继续形成界面余像或其他缓存。

记录、整理、检索和发送遵循同一条可继承的边界。用户可以让某段材料只留在本机、只用于当前话题、不得进入长期记忆，或永远不在主动推荐中出现；由它生成的摘要、卡片、推荐和任务不会偷偷越过这条边界。需要把一项成果交给外部 AI、公开仓库或其他人时，DCF 会从允许使用的材料中形成一份去除无关私人来路的交付版本，而不是迫使用户在“全部分享”和“完全不能用”之间二选一。

切换到一个新的 AI 时，DCF 不会把多年历史一股脑塞给它。它会根据当前话题、这次想做的事情和目标 AI 所承担的角色，组装一份刚好够接手的上下文：当前认识、已经确定的约束、仍然开放的问题、必要证据和可继续追溯的来路。愿景共创、严谨工程、闲聊陪伴等不同场面会自然带上不同的相处方式；侧边栏清楚显示这一刻准备带过去的内容，用户可以一眼删改或换一种工作姿态。

DCF 不只在用户切换窗口时完成一次串行交接。它同时是网页 AI 与本地 IDE 之间的持续协作桥梁：网页 AI 可以在当前对话中发起对本地代码、文件和运行环境的查证、修改或验证请求；IDE Agent 也可以把现场观察、代码差异、测试证据、阻塞和需要进一步判断的问题送回网页 AI。双方围绕 DCF 持有的同一任务多轮往返，用户不再充当复制对话、搬运日志和重新解释任务的通信协议。

这种协作不是把两边的完整聊天互相倾倒。DCF 为同一项工作保留共同目标、已经形成的决定、当前状态和连续事件线，再分别给双方提供适合其角色的视图：网页 AI 看见足以继续判断的现场事实与证据，IDE Agent 得到足以行动的目标、约束、仓库语境和验收要求。IDE 对本地现场的观察不会被网页 AI 的猜测覆盖，网页 AI 的解释和方案也不会冒充已经发生的工程事实；用户仍然拥有目标、价值取舍和最终验收。

协作可以从任意一端发起。网页 AI 发现当前判断需要真实仓库证据时，可以通过 DCF 请 IDE Agent 调查；IDE Agent 在执行中遇到设计含义、需求来路或跨话题判断时，也可以带着必要现场材料回问网页 AI。一次协作被用户开启或任务被确认以后，普通的提问、进度、证据与复验可以自动往返，不要求用户逐条批准；新增权限、扩大范围、破坏性动作或真正改变目标的分岔则会回到用户面前。侧边栏让整个往返可见、可暂停、可改向，用户随时能够接管，但不必长期站在中间当调度员。

### 职业朋友共同长出的世界

这套愿景会继续邀请具有不同工作、生活经验和个人趣味的朋友一起畅想。这里的“角色”不是需求评审器、目标用户模拟器，也不是准备塞进 DCF 的内部岗位；他首先是一个真正听见当前构想、愿意和用户继续聊天，并会被其中某些可能性打动的人。

专业经历不会把他变成一张固定检查表，却会自然改变他先看见什么。长期承担的工作规范塑造了他的痛点、警惕点和安全感，亲手做过的事情塑造了什么会让他觉得顺、觉得别扭，个人爱好则决定哪一部分最容易点燃新的联想。因此，不同朋友不是对同一套问题换一组术语作答，而是会从同一个 DCF 中看见不同的未来，并本能地伸向那些当前构想尚未说透、甚至还没有意识到的空白。

他带回来的首先是一幅自己也想住进去的画面，以及由此长出的设想和愿望，而不是对现有方案的审查结论。用户与 AI 再一起感受这项联想是否让共同世界变得更完整；被接住的部分会与既有愿景重新织成一个整体，尚未被接住的部分仍只是这位朋友贡献的可能性。职业规范可以帮助暴露盲区，却不会因为来自专业人士就自动升级为产品要求。

#### 一人机构与专题卷宗

从调研员朋友的视角回看这套构想，DCF 显出的整体形状不是“增加一个调查功能”，而是逐渐长成一座只服务于一个人的机构。材料库像档案馆，长期梳理像研究与分析部门，侧边栏像随身情报台，网页 AI 与 IDE Agent 是可以随时更换的研究席和工程席，共同任务则让不同席位围绕同一件事持续工作。用户不会被这座机构擅自对象化，也不需要亲自承担它的行政运转；用户是委托人、总编辑和最终指挥，决定什么值得关心、什么进入现实、什么才算真正完成。

这座“一人机构”需要一种介于单张卡片、宽泛 Wiki 与执行任务之间的长期形态：专题卷宗。它围绕一个持续存在的问题、项目或判断，把散落多年的原始对话、不同版本的观点、关键转折、现实证据、关联卡片、正在进行的任务和当前认识组织在一起。卷宗不是把资料复制到一个新容器，而是给已经存在的材料建立一条可继续生长的研究视图；任何网页 AI、本地模型或 IDE Agent 都可以拿到适合自己工作的切面。

专题卷宗让 DCF 不只回答“我现在怎么看”，还可以回答“我是怎样走到这里的”。当一个判断几次被现实修正，DCF 能沿着认知航迹指出每次变化发生在哪里、由什么证据或经历推动、哪些旧解释已经退出当前默认。长期材料因而不只是可搜索的内容，也成为可以回看、比较和重新研究的个人认知历史。

用户也可以主动把授权范围内、与自己有关的积累设为研究主题，临时邀请任何合适的 AI 做一次专题研究：某类想法通常怎样成熟，哪些问题反复被错误地拆成局部补丁，什么样的对话最容易带来真正的新认识，哪些任务总在相同条件下停住。谁发起研究、为了什么、使用哪些材料都会随结果保留，AI 的归纳不会冒充对用户身份的最终定义。研究结果可以形成一份可追溯的专题简报、补进既有卷宗，或磨成新的卡片与方法；它不要求 DCF 永久增加一个“调研员角色”，而是让不同心智气质都能从同一份生活材料中照出新的结构。

#### 可持续改造的个人软件世界

从全栈工程师朋友的视角看，DCF 最让人兴奋的延伸不是增加一种“编程模式”，而是让用户眼前的数字世界逐渐变成可以现场改造的东西。网页、桌面工具、IDE 和本地服务不再只是已经定型、只能适应的产品；用户在哪里感到不顺手，就可以直接指着那个界面、动作或结果继续和 AI 讨论，DCF 则把当前现场与本地实现能力接到一起，让这个愿望从一句话自然进入真实修改。

当前正在使用的软件本身就是共同工作台。用户可以圈中一个界面区域、重做一个交互，也可以只说清此刻哪里别扭；DCF 会把足以理解问题的可见界面、操作位置、当时状态和相关材料带给网页 AI，再把已经形成的意图交给 IDE Agent。若这是用户拥有源码的项目，修改可以从当前界面一路追到前端组件、接口、数据与后端逻辑；若这是第三方网站或无法直接修改的工具，同一个愿望则可以落成只属于用户的界面覆盖、浏览器补丁、自动化或跨站连接。用户不需要先判断这究竟是前端、后端、插件还是脚本问题。

这条修改回路始终回到原来的生活现场中完成：候选变化先在用户眼前出现，实际操作直接检验它是否舒服；不合适就继续改或立即撤回，合适才留下。小改动不必先升级成项目、写任务书和进入管理流程；当它自然牵动多层代码、多个软件或较长执行时，同一条修改脉络再长成由 DCF 持有的持续任务，不要求用户重新交接一次。

一次成功修改留下的不只是一段代码。DCF 会一起保存它想改变的真实体验、适用对象、当前实现、怎样判断仍然有效以及如何撤回。由此形成的“个人补丁”可以跟随用户继续生活：目标软件改版后，旧实现即使失效，原来的意图与行为验收仍然存在，新的 AI 可以据此寻找适合当前版本的实现，而不是让用户重新回忆几个月前为什么写过这段选择器或脚本。

当同类修改反复出现，个人补丁还会继续长成可复用能力。原本散落在几个网站和本地工具之间的一串动作，可以被捏成一个只服务于用户的微型工具、跨站流程或侧边栏能力；它不要求原有产品彼此认识，也不要求用户等待厂商提供集成。DCF 因而不只让过去的思想再次说话，也逐渐保存用户亲手为自己塑造出的可执行数字环境。

侧边栏在这段生活里也不需要另开一套工程后台。平时它仍然是卡片、搜索、火花和任务的显性入口；当用户开始指向一个真实界面并提出修改时，同一个位置自然展开为现场工作台，让用户看到当前对象、正在形成的变化、可试用的候选和撤回入口。网页 AI 与 IDE Agent 在背后持续协作，用户则留在真正想改善的那件事上，而不是被迫进入另一套开发管理生活。

#### 候选与带条件的可信地面

从 QA 朋友的视角看，全栈工程师让数字世界变软以后，真正令人安心的下一步不是给每项修改补一张测试报告，而是让这片可塑的世界始终保有可以放心踩下去的地面。他最想住进的未来，是用户可以大胆尝试任何改变，却不必拿已经好用的生活作赌注：新的实现先成为与当前状态并存的候选，原有实现、适用前提、证据与撤回路径不会丢失；前提仍成立时可以继续使用或退回，前提失效时则诚实进入“需要复验”或“当前未知”。只有候选在该经过的构建、确定性检查和真实使用中证明了自己，它才接替原来的位置。

DCF 因而不会只保存“这次改了什么”，还会逐渐记住用户真正依赖哪些生活动作，以及这些动作为什么曾被用户认可。用户在原来的场面里完成一次操作并说“对，这就是我要的”时，系统会把这次认可背后的愿望、必要条件、实际动作和可观察结果连成一条个人验收路径。它保留的是证明这项体验仍然成立所需的最小现场，并继承原材料的隐私边界，而不是把用户此后的每次操作都变成监控录像或测试负担。

这里的可信不是覆盖整个系统的一枚绿色徽章，而是某项具体承诺在某个实现、某种环境和某个时间点上有证据成立。例如，代码能够构建、自动检查已经通过、候选在模拟页面中跑通、用户真正依赖的动作在真实页面中完成，分别证明不同层次的事情，不能彼此冒充。当网站、依赖、权限或运行环境改变并触及某条证据的前提时，只有相关能力进入“需要复验”或“当前未知”，其他未受影响的能力仍保留自己的可信状态。旧报告不会因为曾经是绿色，就永远冒充今天的事实。

测试也不会反过来成为高于用户愿望的权威。个人验收路径保护的是用户仍然认可的生活，而不是把过去的偏好冻结成永久规范。用户改变目标时，原来的路径与证据退回历史位置，新的愿望重新决定什么值得证明；如果只是实现变了而愿望没有变，既有路径才继续守住同一项承诺。

一次真正逃过验证的故障也不会只留下“这回修好了”。DCF 会在同一个故障身份下冻结足以继续调查的 QA 证据层：用户刚才想完成什么、实际走过哪几步、运行的是哪个候选、当时环境与可观察结果是什么、它与最近一次可信结果差在哪里。网页 AI 和 IDE Agent 可以直接从这份现场继续，不要求用户重新复现、收集日志或证明自己确实遇到了问题；修复通过后，这条曾经失败的生活路径会成为以后持续守护同一能力的证据。

用户日常看到的仍然不是一座 QA 控制台。侧边栏只在需要时说清哪项能力仍可信、哪项因为什么变化失去了当前证据、候选还差哪一种现实确认；背后的构建输出、运行记录和原始证据可以逐层展开，但整理与比对由 DCF 承担。QA 朋友向往的不是一个永不出错的系统，而是一个从不把未知伪装成成功、也从不让用户为获得可信而兼职做测试员的系统。

#### 可理解且可继续的变化

从代码审查员朋友的视角看，QA 已经回答了“这项承诺此刻有没有被证明”，但一个能够长期居住的个人软件世界还需要回答另一件事：这次实现究竟把什么带进了系统，它有没有悄悄改变别处的关系，几年以后是否仍有人能够读懂、替换和继续修改它。全栈工程师让数字世界变软，QA 让脚下仍然可信；代码审查员则希望它被反复塑形以后，依然看得懂、拆得开、改得动。

每次变化因此不只携带代码差异和验证结果，还会保留一条可以重新理解的“变更论证”：它源自用户哪项愿望，为什么选择当前实现，改变了哪些承诺与边界，引入了什么依赖、权限或假设，哪些路线曾被放弃，以及在什么条件下应该撤回或重做。这不是要求开发者事后补写一篇报告，而是让意图、讨论、实现与现实证据本来就属于同一项变化。无论未来换成哪个 AI 接手，都不需要从代码形状反猜它为什么存在。

代码审查员尤其敏感于代码差异与真实影响之间的不对称。几行看似局部的修改，可能把暂时观察变成权威事实、把一次界面便利变成永久平台依赖、扩大一段私人材料的可见范围，或者让一个可替换模块开始掌握整个系统的存活；相反，一次改动很大的重构也可能因为消除了多份半权威状态而让世界更简单。DCF 因而需要让用户看见的不只是“改了哪些行”，还有这次变化在目标、事实所有权、数据流、权限、恢复与未来替换能力上的语义差异。风险不再是一枚笼统的高低标签，而是一张能够说明影响从哪里传到哪里的关系图。

审查意见也不会变成必须逐项消灭的红点。它首先是一项带着依据、成立条件和潜在后果的风险判断。用户完全可以为了眼前价值接受一处被隔离、可撤回的粗糙实现；DCF 会记住当时为什么值得这样做，不让后来的 AI 一遍遍重复同一句“最佳实践”。当原有条件改变、同一种权宜做法开始在多处复制，或它的影响半径越过原先边界时，这项风险才重新醒来，并说清这一次究竟发生了什么变化。

他最喜欢的未来不是让所有个人补丁都接受企业级治理，而是让系统在积累个性化能力时还有机会越长越简单。几个补丁如果不断绕过同一个缺失关系，DCF 会逐渐看见它们其实是同一个源头问题的不同症状；新的建议不再是为每个症状增加保护分支，而可能是补上一项更基础的能力、收回一份错误权威，或删掉已经失去必要性的整层结构。用户获得的功能越来越多，理解和更换它们所需承担的复杂度却不必同比增长。

用户日常也不会面对一场无穷无尽的代码评审。确定性的漏洞扫描、依赖检查、契约比对和重复模式识别可以在背后持续完成；只有真正涉及价值取舍、权限扩大、不可逆后果或未来自由度的差异才来到共同工作桌。代码审查员真正向往的是：任何 AI 都可以为用户贡献代码，却没有哪项能力会成为只有当时那个 AI 才能解释的神秘遗产。DCF 可以越长越强，但不会越长越神秘。

#### 可重返的界面现场

从 UI 操作者朋友的视角看，QA 已经让每项承诺携带持续可信的证据，但界面世界还有一种更容易消失的事实：用户刚才究竟看见了什么、碰到了什么，以及那个异常是在怎样的连续动作中第一次显现。许多最真实的 UI 问题只活了几秒——弹层一闪而过、焦点被悄悄夺走、按钮明明存在却被透明区域挡住、滚动位置在等待结果时突然跳回去。等用户开始描述，那个现场往往已经不在了。

他最想要的不是让用户更熟练地录屏、截图和编写复现步骤，而是让“刚才这里不对”本身成为足够有效的指向。在允许观察的界面范围内，DCF 可以在本机保留一段短暂、自动消逝的界面余像；进入“不读取”的窗口不会产生这层缓冲。当用户指出异常，或正在验证的路径出现可见偏差时，DCF 才冻结与这件事有关的最小片段。用户能够倒回那个瞬间，沿着时间看见异常之前的动作、第一帧不对发生在哪里，以及随后状态怎样继续变化。没有被选中的余像自然消失，不让“可回放”变成对全部数字生活的永久监控。

这个被留下的界面现场不只是一段视频。可见画面、鼠标与键盘动作、焦点、悬停、选区、滚动、窗口与视口、当时运行的候选和环境共同保持在一条时间线上；页面结构、辅助功能信息、事件、请求和日志则作为能够解释原因的观察层与它对齐。源码说元素存在、DOM 能找到、点击事件已经触发，都不能覆盖“用户眼前没有看见或根本点不到”这一事实；反过来，一张像素截图也不会被迫独自承担因果解释。

于是可视化 Bug 不再被压缩成几张图片和一句“偶现”。它成为任何合适的 AI 都能重新走进去的活现场：可以停在第一帧异常处，从用户看到的表面逐层追到结构与运行原因；也可以从同一现场分叉，让旧可信版本与修复候选同步重走一遍，直接看变化发生在何处。原问题即使后来无法再次触发，第一次真实发生过的现场仍然保留为 observed，而不会因为自动重放暂时成功就被改写成“无法复现”。

UI 操作者还会天然注意真正端到端路径中那些经常被测试工具剪掉的边界。网页内容、扩展侧边栏、浏览器自身界面、系统权限框和文件选择器可能分别处在不同的可见与可控范围内。DCF 不会因为自己跑到了某一层末端就宣布整条路径通过；界面现场会明确显示哪一段被实际看见、哪一段只收到内部信号、哪一段仍需要另一个观察者或用户判断。工具的视野边界本身也成为证据的一部分。

在他喜欢的未来里，视觉对比也不是让像素差分替用户决定好坏。候选可以与旧版本并排、重叠或同步回放，DCF 自动指出遮挡、错位、截断、跳动和交互目标变化；但布局是否更舒服、层级是否更清楚、一次有意重做是否值得接受，仍由用户在真实动作里判断。一次认可留下的是界面关系、操作感受和适用场面，而不是要求未来永远复制旧截图。这样 UI 可以持续变化，却不会每次变化都让“这里为什么曾经这样才好用”重新丢失。

由此，同一个故障身份中会多出一种与对话、代码和测试都不同的现实材料：可以重新进入的界面现场。它让用户语言中大量依靠眼前世界才能成立的“这个、那里、刚才、这样”拥有长期可追溯的所指，也让一次可视化故障从需要用户反复表演的问题，变成能够被 AI 直接接手、比较、修复和重新验证的共同现场。

#### 可证伪的故障诊断

从故障诊断工程师朋友的视角看，UI 操作者已经把会消失的异常现场带了回来，QA 也已经保证它不会被一句“无法复现”或一次绿色重跑抹掉；但真正的诊断还要回答，究竟是什么关系使这次故障得以成立。一次稳定复现只能证明某组条件下现象会出现，最靠近报错的位置也未必拥有缺陷。网络变慢、焦点切换和页面重载都可能只是触发器，错误状态还会沿着几层模块传播，最终才在用户眼前表现为闪空、卡住或送错目标。

他最想住进的未来，是每次真实故障都能逐渐收缩成一个可反驳、可干预的因果对象。DCF 会从同一故障的原始界面现场分叉出一份隔离的“故障分身”，保留让异常成立所需的输入、状态、版本、环境与时序，再从同一位置不断分叉：改变一个条件、撤掉一层状态、交换成功与失败版本、对提交和配置做二分，观察故障在哪里出现、消失或换了表现。故障分身可以承载实验，却不能改写原始现场；它不需要永久复制整个世界，而要逐步找到仍足以让故障成立的最小关系。

这套收缩会明确区分触发条件、潜在缺陷、传播路径与用户看到的症状。根因不一定是一行写错的代码，也可能是一份没有明确所有者的事实、一个缺失的状态约束、一项只在顺利时成立的接口假设，或两个模块都以为对方会完成的责任。只有当改变这项关系能够让一整族触发方式失效，同时保住原本应有的行为，诊断才有资格把它提升为已经得到证据支撑的根因；否则它仍然只是候选解释。

因此，每个诊断假设都会同时携带支持证据、反例、尚未观察到的边界，以及最能区分竞争解释的下一项实验。DCF 不会用一段听起来完整的 AI 故事填满证据之间的空白。无法证明的部分可以保持 probable、unverified 或 unknown；后来出现的新现场也能推翻旧解释，让故障谱系重新合并或拆开，而不是为了维护一份漂亮报告继续替错误根因辩护。

修复建议由此不再是“这里可能加个判断”的灵感清单，而是一项可以被现实检验的因果承诺：准备改变哪条关系，预期哪些症状与触发方式会一起消失，哪些既有能力必须保持不变，会引入什么新风险，以及怎样证明这次只是遮住症状还是确实消除了缺陷。临时隔离、恢复适用前提仍成立的旧实现、根因修复与长期加固可以先后发生，但各自保留真实身份；用户可以先恢复正在进行的生活，而故障不会因为表面已经可用就被提前结案。

随着这样的诊断积累，DCF 会逐渐形成故障的因果记忆。几次看似无关的异常如果共享同一项基础缺陷，会被重新看成同一个故障家族；一次修复如果只让旧症状换了入口，也会被旧因果承诺识别出来。诊断所需的额外观察只在可疑边界临时长出，得到足够证据后便缩回或消逝，不让个人软件环境为了随时可能发生的故障永久背负一座监控中心。故障第一次出现仍然可能是意外，但从那以后，它开始成为系统理解自身边界、并让整类问题失去生存条件的材料。

QA 证据层、界面现场与故障分身因此不是三份独立保存的故障真相。前者说明哪项承诺在什么条件下失效，中间一层保存用户实际经历了什么，后者负责改变变量并检验因果解释；三者共享故障编号、候选身份、环境和隐私边界。代码审查员随后审查修复候选改变了哪些关系，不再建立第四份故障事实。

### 卡片、火花、推荐与持续任务

侧边栏也不是一个只展示固定收藏的卡片架。用户可以从这里发起搜索，DCF 会越过当前页面，搜索卡片、私人仓库、材料库以及其他保存着相关资料的位置，把同一话题下的观点、来路和支撑材料重新聚到一起，并结合当前对话组织成可以直接回复的内容。卡片提供即时出手的速度，全域搜索则在需要时调动背后的完整积累；用户不需要知道资料实际落在数据库、GitHub、Wiki 还是其他位置。

积累变大以后，侧边栏仍然只把少量真正与当下有关的东西摆在前排，其余内容进入可搜索、可重新唤醒的深层材料中。它会区分四种不同的浮现：卡片是现在就能拿来用的积累，火花是此前分离的话题突然产生的新联系，推荐是 AI 带着来源与理由提出的行动建议，任务则是用户已经接住、由 DCF 持续拥有的行动。不是每个新联系都被催成推荐，不是每个成熟建议都被冒充成用户目标，也不是每张旧卡都靠频繁出现证明自己存在。

系统还会从对话中寻找尚未实施的创意和已经浮现但没有进入行动的方向。当一个方向已经能说清它会带来什么帮助、现有材料足以形成可执行起点，并且存在具体的下一步时，系统可以把它整理成推荐卡；尚且只是灵感的东西继续留在原有话题中生长，不被过早压成待办。成熟度只决定一项想法是否具备被推荐的条件，不会把 AI 的提议升级成用户意图。

推荐卡不是一堆等待用户重新筛选的平铺待办。每张卡会显现高、中、低优先度，帮助用户一眼辨认哪些方向更值得先占用注意力和执行资源。优先度同时考虑可能带来的实际帮助与兑现难度：价值大、材料已经成熟或容易实现的方向可以更靠前；只是在现有体验边角上缝补、即使完成也不会带来明显变化的事项可以留在低优先度。优先度是系统带着依据给出的判断，不是用户已经作出的排序，也不替用户作最终选择。

用户可以在一次推荐发掘开始前主动给出当下偏好，例如这次更想处理记忆，下一次更想寻找自动化方向。系统会带着这束临时的探照灯重新探索既有对话，重点聚拢相关创意、未竟方向和已经成熟的材料，再形成这一轮更贴近用户兴趣的推荐。偏好改变的是本次发掘重心，不要求用户重建长期分类，也不把材料库永久收窄到一个主题。

定向偏好是重点而不是永久过滤。通常只有相关推荐进入这一轮视野；如果系统同时发现一项与偏好无关、却明显更有价值或错过时机就会失效的方向，可以另行亮出并说明它为什么值得打断本轮方向，而不能借此重新塞回一大堆普通待办。用户暂时不想做、明确放弃或认为判断错误的推荐会退出当前视野；DCF 记住当时为什么不做，只有价值、条件、时机或用户方向真的改变时，它才带着“发生了什么变化”重新出现。推荐优先度随现实成熟或衰退，不会成为永久等级。

只有用户接住一项推荐后，它才成为任务。此时持续拥有任务的不是某个临时 AI 会话，而是 DCF；系统可以自动唤起本地 AI 接手，目标、来路、边界、当前进度、关键决定和可恢复检查点则留在任务自身。一个执行者失败、额度耗尽或不再适合时，另一位执行者可以从真实进度接手，不要求用户重新讲述整件事。执行期间，只有新的价值选择、越界权限或无法从既有材料判断的分岔才回到用户面前，普通的工具切换、恢复和证据整理由 DCF 承担。

“已完成”必须由结果和验收证据共同支撑。任务可能处于执行中、等待用户判断、受阻、失败、已经产出但尚未验证，或真正通过；不能证明完成时就保留在真实状态。本地 AI 完成工作以后，成果、证据、失败路线、改变的认识和仍未解决之处会分别回到它们所属的话题，而不是把执行日志原样倒进材料库。DCF 因而形成一条持续循环：对话成为材料，材料长成知识、能力与推荐，用户接住的方向进入行动，行动结果再成为新的材料。

| “已经复现”常被误当成“已经找到根因” | 从真实失败建立隔离的故障分身，逐项改变输入、状态、时序、环境、版本与配置，持续压缩成功现场和失败现场之间的差异 | 能够自我收缩的最小故障条件；复现成为因果探索的起点 |
| 日志中的相关性很容易被讲成确定因果 | 每个候选解释同时摆出支持事实、反例、未知边界与一项能够区分竞争解释的实验，新的证据可以直接推翻旧判断 | 可证伪的诊断假设；AI 的解释必须服从实验，而不是靠完整叙事获得权威 |
| 真正的缺陷往往不在最后报错的那行代码 | 追过模块传播之后，发现问题来自事实没有唯一所有者、接口责任缺失、状态约束不成立或恢复语义相互冲突 | 诊断对象从代码位置上升到使故障成立的基础关系，修复可以让整族症状自然消失 |
| 用户需要先继续生活，根因调查却可能仍需时间 | DCF 先隔离影响，或退回适用前提仍成立的旧实现，同时让原故障在分身中继续调查；恢复、根因成立、正式修复和加固分别保留状态 | 表面恢复不再冒充故障结案；快速止损与深入诊断可以并行存在 |
| 一条局部补丁很容易只改变症状的出口 | 每项修复建议说明准备改变什么、预期消除哪些触发方式、必须保持哪些行为、可能新增什么风险，以及怎样证明它没有只遮住问题 | 修复建议成为可执行、可反驳的因果承诺，而不是猜测式代码清单 |
| 为诊断永久采集一切会让系统越来越重，也会侵犯生活边界 | 观察探针只在当前假设指向的边界临时长出，收集足以区分解释的最小证据，诊断结束后自动缩回 | 按需生长的可观察性；个人系统获得诊断能力而不变成常驻监控中心 |
| 相似故障在不同月份、模块和入口反复重来 | DCF 将新现场与既有故障谱系比较，识别旧缺陷换了触发方式、旧修复失效，或多个现象其实共享同一根 | 会积累的因果记忆；每次故障都提高系统消灭一类问题的能力 |

## 连续生活草稿

用户照常在不同 AI 之间生活。白天在网页 AI 中讨论项目，晚上让本地 AI 写代码，间隙里又随口聊到一个暂时不会实施的念头。观察与归档边界已经由他按窗口和场面选择；在允许归档的范围内，他不需要再停下来判断哪句话属于知识、哪段对话值得保存，也不需要因为换了平台而重新管理一套历史。

授权归档的现场连同当时真正看过的附件、代码版本和工具结果一起回到材料库。某个网页改版曾让一段本应记录的 IDE 对话没有被完整读回，DCF 没有照常亮起“同步成功”，而是在那条时间线上留下了一处清楚的缺口；等来源恢复后，它自行补回能够确认的部分，仍无法找回的几分钟继续保持缺口。几年以后，无论用户还是 AI 都不会把一段残缺历史误当成完整事实，也不会把用户主动排除的生活误报成系统故障。

当天的梳理也不会把每句话都加工成人格档案。用户深夜随口说了一句“以后干脆全让 AI 自己决定算了”，它会留在那场情绪和玩笑都很明显的对话里，却不会第二天变成“用户偏好完全自治”。真正反复出现、被用户明确采用或已经在现实中验证的认识，才慢慢进入 Wiki、记忆和卡片。AI 曾经提出但用户没有接住的主张仍然能被找到，只是不会被冒名写成用户的立场。

有个方向聊到一半后被现实打断，三周没有再碰。用户下一次打开相关仓库时，DCF 没有扔出十七场历史会话让他复习，而是在侧边栏把当时的续接点递回来：已经确认了哪两件事，哪项判断只是 AI 的推测，最后一次实验失败在哪里，以及那时为什么没有继续。点开任意一句都能回到原始现场。用户不必恢复全部历史，只需要重新回到自己当时那一步。

一天里的切换也不要求用户重新进入 DCF。上午，他在网页 AI 中自由孕育一个还很松散的方向，侧边栏给当前 AI 带上适合共创的相处方式，只送入这次真正相关的积累。下午，他把注意力移到本地 AI，DCF 换成适合私密材料和深入推理的上下文。晚上进入 IDE 时，它又把已经形成的目标、约束、待验证假设和仓库证据组成一份工程接手包，而不是把上午的整段闲聊直接塞进编程 Agent。用户始终面对的是同一个 DCF；变化的是它此刻伸向哪个 AI 的眼睛、手和说话姿态。

有一天，用户不是想找一张现成卡片，也不是准备立即立项，而是突然想知道：自己这些年关于“AI 能不能承担需求判断”的认识到底经历了什么变化。他从当前对话里点进专题卷宗，眼前没有出现一份机器替他盖棺定论的性格报告，而是一条仍能回到现场的认知航迹：最初的模糊不适、几次争论里被推翻的说法、真实项目中暴露出的差别，以及当前判断为什么比旧版本更准确。

网页 AI 从这份卷宗里看到的是不同论点、转折与仍有张力的地方；IDE Agent 如果参与，则只收到与真实工程案例和验证有关的切面。用户请当前 AI 把整个专题做一次研究，它又从多年材料里发现：许多被称为“AI 编程能力不足”的问题，其实都在更早的位置缺少明确目标和最终价值判断。这个跨话题结构被写回卷宗，也凝结成一张随时可以发射的锋利观点卡。

几个月后，新的项目经验让这条观点需要修正。DCF 没有把旧简报继续当成永恒结论，也没有删除当初为什么会那样想；专题卷宗把新证据接到原有航迹上，让用户一眼看到这次究竟改变了哪一层。这样，调研带来的不是一个必须常驻的新 Agent，而是用户随时可以借任何 AI 的眼睛，重新研究自己已经走过的生活。

但这次进入 IDE 并不意味着网页对话已经交接完毕、可以关掉。网页 AI 在讨论中意识到，自己的一个关键判断取决于仓库里究竟谁拥有那份状态，于是直接通过 DCF 向 IDE Agent 发出调查请求。IDE Agent 在真实代码与运行环境中检查后，把定位到的实现、观测结果和仍无法证明的部分送回来。DCF 没有把一整屏终端输出塞进网页聊天，而是保留完整证据，同时把网页 AI 继续判断所需的部分带回原来的话题。

网页 AI 据此推翻了原先的假设，重新说清真正该改的关系，并把新的目标和验收边界交给 IDE Agent。执行到一半，IDE Agent 发现两种改法会分别牵动数据连续性和系统简洁度；它没有在代码现场替用户偷做价值选择，而是带着差异和影响回到共同工作桌。网页 AI 帮忙把问题讲透，用户只需要在原来的对话里校准一句，IDE 便从同一任务继续往下走。

代码完成以后，IDE Agent 把差异、测试和真实运行证据送回；网页 AI 对照最初意图审查结果，又要求补一次能够区分“源码已经存在”和“用户行为已经通过”的验证。整个来回里，用户看得见两边正在做什么，也能随时叫停，却从未复制过一次日志、重写过一次任务书。最后留下的不是两场彼此失忆的聊天，而是一项带着目标、讨论、现场事实、决定、变更与验收证据的完整共同工作。

另一次改变并不是从项目计划开始的。用户正在一个每天都要用的网页里重复完成一串别扭动作，做到一半时直接在侧边栏指向那块界面，说自己希望它就在这里多出一个更顺手的入口。DCF 把此刻的页面、选中的位置、刚刚走过的操作和相关历史带进原来的网页对话；网页 AI 与用户一起把想要的感觉磨清楚，IDE Agent 则在另一端判断这次应修改已有源码，还是只在用户一侧加一层个人补丁。

几分钟后，候选入口已经出现在原网页上。用户照常做了一遍真实动作，觉得位置不对，顺手拖了过去；网页 AI 理解这不是单纯改坐标，而是它应该跟随另一组内容出现，IDE Agent 随即调整实现。整个过程没有先建需求单，也没有要求用户离开当前软件去看一套工程面板。满意后，这次改造连同它解决的真实不适、当前实现、可复现的操作和一键撤回一起留下。

这次满意并没有立刻把一段新代码覆盖到原来的可信状态上。DCF 保留着旧入口，同时让刚才亲手试过的那一份候选携带完整身份继续往前；构建结果、自动检查和用户实际完成的那条动作分别留在它身上。只有这几层证据共同到位，侧边栏才把它显示为新的可信版本。用户没有看测试面板，却清楚知道自己启用的就是刚才真正试过的那一个，而不是测试以后又被重新打包的另一个东西。

半年后目标网站改版，原补丁没有继续静默假装可用。DCF 发现这次页面变化触及了“入口应跟随哪组内容出现”这条承诺的证据，于是只把这项能力标成需要复验，其他个人工具并未一起变红。它带着原来的愿望和个人验收路径让新的 AI 面对新页面重新找落点，再在候选状态中重走相关动作。用户看到的是一份已经能在新版本上试用的修复候选，以及一句仍需他判断的新交互差异，而不是一段报错的旧脚本和一句“请重新提供选择器”。

另一天，一个从未被预料到的边缘状态还是让入口失效了。用户刚刚意识到“不对”，DCF 已经把他原本想做的事、刚才的动作、页面状态、运行版本和异常结果收成同一份现场。IDE Agent 不需要先让用户重演一遍，网页 AI 也不需要根据零散描述猜故障含义。修复回到这条原始路径上通过以后，那次失败没有被埋进日志，而是留成以后每次相关变化都要经过的现实守卫。

类似的改动积累起来以后，其中几项原来分散在网页、AI 和本地文件之间的动作慢慢合成了一个小工具。它没有被迫长成一款面向所有人的产品，只在用户需要的场面里出现在侧边栏，替他跨过那些厂商从未打算替个人打通的边界。DCF 保存下来的因而不只是几年间用户怎样思考，也包括他怎样一点点把身边的软件磨成了更适合自己的形状。

这个小工具第一次准备进入长期使用时，构建、自动检查和真实动作都已经通过；但 DCF 没有因此假装它已经没有值得判断的风险。候选为了省去一次显式绑定，把“此刻获得焦点的窗口”同时当成了以后持续发送结果的目标。它今天确实能工作，代码也只少了几行，可这份语义差异意味着一次暂时观察正在悄悄成为长期权威。侧边栏没有丢给用户一份审查清单，只把真正的分岔说清：保留当前捷径，会换来更轻的实现和以后送错目标的可能；保存显式绑定，则多承担一点结构，却让用户意图不再由页面状态猜测。用户决定哪种生活值得留下，IDE Agent 再沿同一项变化继续。

几个月后，另三项个人补丁都开始为同一种窗口身份问题增加自己的保护分支。DCF 没有把它们当成三个互不相关的代码异味，而是沿着变更来路看见：它们都在补偿同一份基础关系尚未被系统明确拥有。一次新的建议因此不是再加第四个条件，而是把窗口与持续任务之间的绑定收回到一个清楚的位置。候选重构看起来改动更大，却同时删掉三组同步和恢复分支；原有个人验收路径继续证明生活没有倒退，变更论证则说明系统为什么反而变简单了。

再后来换了一批模型接手，新的 AI 不需要相信旧模型留下的自我解释。它能沿着每项能力看到用户原始愿望、真正拥有事实的位置、不能破坏的不变量、当时接受过的权宜风险，以及哪些条件一旦变化就应重新判断。旧实现可以被整块替换，用户多年形成的生活方式却不必和某个作者一起报废。持续维护由 DCF 承担，用户只在真正会改变自己选择空间的地方重新出现。

一次新的异常就发生在这种普通使用中。用户把结果从网页 AI 交给 IDE 后，侧边栏短暂出现了正确的任务状态，随即在一次窗口切换中闪回空白。这个窗口处于允许观察的状态；等他把目光移回来，页面已经恢复，看起来什么都没发生。他只说了一句“刚才这里闪没了”，DCF 便把尚未消逝的几秒界面余像停在面前。

用户沿时间向前拖了一点，看见问题不是“空白页”本身，而是切回浏览器后焦点先落到另一个会话，侧边栏用了那一瞬的临时观察覆盖了仍在持续的任务绑定。他圈住状态文字第一次变化的那一帧。网页 AI 得到的是这段带有所指的现场，IDE Agent 则同时看到候选身份、窗口与焦点事件、页面结构和相关运行观察；没有人要求用户再精确复刻那次偶然时序。

修复候选随后从同一现场分叉重放。旧版本和候选并排经历相同的窗口切换：旧侧边栏再次闪空，候选仍守住原任务。DCF 又换了不同窗口大小与一次更慢的页面加载，找到另一个会触发相同关系错误的边缘；但当路径进入系统文件选择框时，它明确停在自己无法观察的边界，没有把前半段通过写成完整端到端通过。用户最终看到的不是一包需要解释的录屏和日志，而是一段可以亲自走过、随时展开证据层的修复前后现场。

这段界面余像最初只短暂留在本机。用户确认它确实属于当前任务后，DCF 才在同一个故障身份下保存发生故障所需的最小界面现场，其他同时出现的窗口和无关内容自然消失。以后目标页面彻底改版，这份现场也不会要求新界面复制旧像素；它保留下来的是持续任务不应被一次临时焦点覆盖、用户应该始终看见自己正在等待什么，以及这项关系曾经怎样在真实界面中失败。

这次故障没有在“已经可以稳定重放”时结束。DCF 从那段不可改写的原始现场分叉出一份隔离的故障分身，把当时的任务、窗口、会话恢复状态和事件顺序保持下来，再围绕成功与失败之间的差异逐项实验。只让网络变慢没有触发闪空，只切换焦点也没有；当焦点切换恰好落进会话尚未恢复完成的短暂空窗，旧实现才会把一次临时观察写回持续任务的绑定位置。

新的诊断假设因此没有写成“焦点切换导致侧边栏闪空”，而是更精确地说：焦点切换与慢加载是触发条件，临时观察拥有覆盖持续绑定的写权才是候选缺陷，错误值随后经过会话路由传播，闪空只是用户最先看到的症状。DCF 保持原时序不变，只切断这次越权写入，故障消失；再用标签页恢复、会话切换和一次更慢的初始化触发同一条路径，候选修复都守住了原任务。几个此前互不相干的偶现问题由此显出同一个故障家族。

用户不需要等这场调查全部结束才继续工作。DCF 先回到已知适用前提仍然成立的上一份绑定并隔离危险写入，让侧边栏立即恢复；故障分身仍在后台保存为未结案。正式建议随后不是“增加一个延迟”，而是让持续任务绑定拥有唯一写入者，把窗口焦点降回只读观察，并补上一项能够在未来越权时立即显形的状态约束。建议同时说明：这应消除哪些已知触发方式，哪些发送与切换行为必须保持不变，浏览器外壳尚不可观察的部分为何仍然是 unknown。

修复候选通过原故障家族的区分性实验和既有个人验收路径后，根因才从候选解释进入有证据支持的结论。那份诊断留下的不只是复现步骤，而是一条可被未来事实推翻的因果链：哪些条件只是诱因，错误怎样传播，哪项关系被改变后整族故障失去成立条件，以及什么新观察会证明这次判断仍然不完整。半年后如果另一个入口出现相似闪空，DCF 首先比较的是这条因果关系，而不是要求用户从头再讲一遍症状。

有一天，用户正在和一个从未用过的新 AI 讨论问题。这个 AI 又把一组源头相同的故障拆成几十条补丁建议。用户还没来得及重新解释自己的整套判断，DCF 已经在对话旁边亮出了那张长期生长过的“源头化解题”卡片。前排只有几张真正贴着当前语境的内容；几千张旧卡没有为了证明自己存在而挤满界面。

用户看见合适的一张，点一下发射。若现成卡片还不够，他就在侧边栏搜一句。DCF 从几年前的争论、后来形成的知识卡、真实项目中的证据和已经被修正过的旧版本中，组织出这次真正能用的回复。旧观点并没有被偷偷删掉，但当前版本为什么成立、在哪次现实碰撞后发生变化都看得见。用户如果说“这已经不是我的想法了”，这次明确纠正会成为新的演化事实：由材料库拥有的记忆视图随之重算，GitHub 中由用户拥有正文的 Wiki 或卡片则收到带差异的修订候选；原始对话不被篡改，修正本身也能撤回。

更多时候，DCF 浮上来的甚至不是任务。它可能在侧边栏安静放出一枚“火花”：半年前关于动态抽象层级的讨论，刚好与今天在 IDE 中遇到的 Agent 可观察性问题接上了。用户可以顺着它继续聊，也可以让它睡回材料库。生活不会因为所有东西都能被分析，就被迫变成一条永远催促执行的生产线。

某个一直没有落地的创意则真的逐渐成熟。DCF 把它连同来历、已经想通的部分、仍然存在的空白和为什么现在值得做，一起整理成高优先推荐。那些只会改善一点边角手感的修补仍被保留，却不会和一次可能改变整段生活的能力生长挤在同一高度。用户说“这轮先看记忆”，系统就沿着记忆方向深挖；上次被用户以“现在没有合适执行条件”为由放下的建议不会再次原样出现，直到它能明确说明条件已经发生了什么变化。

用户点下确认后，本地 AI 开始执行。两小时后原来的模型额度耗尽，任务没有跟着那个临时会话死掉：目标、关键决定、已经修改的内容、验证证据和下一个可恢复点都留在 DCF 的任务里，新的执行者从真实进度接上。普通恢复不需要用户当项目经理；只有当任务碰到“要不要牺牲数据连续性来换取更整洁的架构”这种真正属于用户的价值选择时，侧边栏才把它带回来。

最后代码已经生成，但真实浏览器行为还没有通过，任务因此显示为“已产出，尚未验证”，而不是提前庆祝完成。验证通过后，代码、文档、证据、失败过的路线和最终改变的认识分别回到原来的材料关系中。下一次走近这个话题时，用户看到的不只是“以前做过”，而是哪些能力已经可信、哪些边界仍然未知。

一段更私密的对话发生时，用户随口说“这个只留本机，也别拿来主动推荐”。DCF 仍能在被允许的本地范围内帮助他继续，却不会把它抽成 GitHub 卡片、长期画像或未来任务。后来其中一个不含私人来路的工作方法确实值得分享，DCF 重新从允许使用的材料中做出一份干净的交付卡；用户不必在泄露整段生活和彻底放弃成果之间选择。

有些稳定流程最终长成了 MCP 插件。它们先在工具架旁说明自己能做什么、会接触哪些内容、验证是否通过，用户确认后才成为可调用能力。某次更新把流程弄坏时，如果旧版本的适用前提仍然成立，DCF 就沿着保留的撤回路径恢复它；如果外部环境已经让旧证据失效，则明确进入待复验或未知。多年积累的知识和任务记录不会被一个坏插件一起拖走。

这样的循环重复几年以后，平台已经换过几拨，模型也不再是最初那批。GitHub 私库和材料出口仍然是用户自己能读懂、能带走的东西，新一代 DCF 可以从它们重新长出索引、卡片和任务关系。真正连续下来的不是某个产品，也不是某个 AI 的记忆，而是用户自己的生活、判断和未竟之事始终有地方继续。

## 愿景演化记录

### 2026-07-26：建立全新起点

用户明确要求不把旧 DCF 的架构、模块和既有结论当作新愿景的预设前提，而将 DCF 视为空白系统重新生长。这并不抹除用户过去的生活；旧对话只有在保留来路、重新参与当前理解时才作为材料进入。第一块被放入这个系统的能力，是在用户授权边界内跨本地与网页、跨闲聊与任务的完整 AI 对话记录，以及由此形成的对话材料库。

### 2026-07-26：材料库获得代谢与行动循环

用户将材料库从被动归档扩展为持续运行的循环。系统会定期用 AI 梳理授权归档的对话，聚合相近话题，形成 Wiki、记忆、知识卡、MCP 插件等既可供用户阅读、也便于 AI 检索和调用的产物；同时从未实施的创意中整理带有来路的推荐。推荐只有被用户接住后才成为任务并交给本地 AI 执行，执行后的资料与新认识再回灌材料库，成为下一轮生长的材料。

### 2026-07-26：推荐获得优先度与用户定向发掘

用户进一步明确，推荐卡需要显现高、中、低优先度。优先判断不仅看方向是否已经成熟，还要看它能给真实生活带来多大帮助，以及当前是否容易兑现；只是对体验进行边角修补的事项应自然沉到较低位置。用户仍保留选择权，并可在某次推荐发掘前给出“记忆”“自动化”等当下偏好，让系统重点回看相关对话、发掘创意并形成候选建议。由此，推荐发现不再只是系统单向排队，而成为系统长期判断与用户当下方向共同决定的一轮探索；AI 的排序仍不等于用户已经拥有这个目标。

### 2026-07-26：积累获得显性作战界面

用户明确否定把 DCF 塑造成无感、沉默的幕后系统。经过梳理的对话设定、锋利观点和稳定流程可以同步到指定 GitHub 私人仓库，由 DCF 拉取；同时 DCF 以看得见的侧边栏站在当前对话旁，把提炼后的观点呈现为可直接发射的卡片。用户也可以从界面搜索跨数据库、仓库和其他材料位置的全部相关资料，让系统聚合出当前可用的论点与回复。由此，长期材料不仅在后台被保存和加工，也能在需要的一刻重新进入用户的手和声音。

### 2026-07-26：侧边栏跨越所有 AI 界面

用户进一步明确，侧边栏支持的不只是网页 AI，而是网页、本地和 IDE 工具中的所有 AI。它会在用户允许观察的窗口中辨认当前 AI 环境，并切换到对应的发送和解析工具；进入“不读取”的窗口则停止观察。由此，DCF 的显性界面不再属于任何单个平台，而成为在授权边界内跟随用户注意力移动的统一操作层：用户始终使用同一套积累和入口，DCF 负责适应眼前不同 AI 的交互方式。

### 2026-07-26：持续使用使 DCF 开始承担连续性

将现有愿景真正放入数周、数年尺度的生活后，材料不断增加所引出的核心需求不再是更多归档类型，而是由 DCF 承担跨时间、跨 AI、跨执行者的连续性。它需要保留话题中断时的认知位置，区分 AI 提议、用户探索、当前判断与现实证据，按当前场面组装适量上下文，并让侧边栏在积累增长后仍只呈现值得进入当下的内容。自动整理必须可追溯、可纠正、可撤销，隐私边界会随衍生产物继承；确认后的任务由 DCF 而非临时 Agent 持有，并以检查点、真实状态和验收证据跨执行者延续。由此，授权范围内的完整记录不再把用户困进一座越来越重的档案馆，而开始真正替用户保存“我走到了哪里，以及下一次怎样从这里继续”。

### 2026-07-26：网页 AI 与本地 IDE 进入同一协作回路

用户进一步明确，DCF 不只是让同一侧边栏依次适配网页 AI、本地 AI 与 IDE，也要成为网页 AI 连接本地 IDE 的桥梁，使双方围绕同一项工作直接沟通和持续协作。网页 AI 可以向本地现场发起查证、执行和验证，IDE Agent 可以把观察、差异、证据与需要判断的问题送回；DCF 持有共同任务、保存双方来路并为各自组装适量材料。普通协作往返在一次开启后可以自动继续，新的权限、范围扩大、破坏性动作和价值分岔仍由用户决定。由此，用户从人工转述与日志搬运中退出，却仍能在显性侧边栏中看见、暂停、改向和接管整段协作。

### 2026-07-26：调研员视角揭示“一人机构”与认知研究能力

用户澄清，调研员并不是 DCF 的目标用户、常驻 Agent 或待新增的“调查态”，而是一位参与愿景共创、会因自身经验产生独特联想的朋友。此前把这一视角直接产品化为独立调查对象属于误读，现已从当前愿景撤回。

从正确视角重新看，调研员首先会追踪 DCF 的整体信息链、现场完整性、材料转化、当下相关性、跨 AI 分工、长期观点演化与系统可迁移性。由此显出的新整体不是一个调查模块，而是一座只服务于用户的“一人机构”：不同 AI 像可替换的研究、分析和工程席位，DCF 则保存共同档案、工作连续性与用户的最终控制。卡片与宽泛 Wiki 之间进一步长出专题卷宗，用来承载一个长期问题的材料、认知航迹、现实证据、关联任务与当前理解；用户可以主动邀请任何 AI，在明确目的与授权材料范围内研究自己的认知历史，但不会被系统擅自对象化，AI 的归纳也不会冒充用户身份的权威定义。

### 2026-07-26：全栈工程师视角让数字世界成为可持续改造的现场

全栈工程师同样不是来评审架构、检查实现条件或成为 DCF 内部的一种角色，而是一位会因热爱修改前端、后端与跨站工具而自然贡献联想的朋友。他听见跨 AI 侧边栏与网页 AI—IDE 协作桥梁后，首先看见的是用户眼前的任何软件都能变成现场工作台：不顺手之处可以被直接指出，愿望从当前界面一路进入前后端或个人补丁，修改结果又回到同一动作中立即试用和调整。

这层联想进一步让一次修改留下了比代码更完整的生命：原始意图、适用现场、当前实现、行为验收和撤回办法共同组成能够随目标软件继续演化的个人补丁；反复出现的补丁还可以长成跨站流程、微型工具和侧边栏能力。由此，DCF 除了保存用户的对话、认识与任务，也开始承载一层由用户亲手塑造、能够迁移和再生的个人软件环境。用户不必先理解技术层次或进入工程管理流程，软件则从要求用户不断适应的固定成品，逐渐变成可以围绕用户生活持续变软的材料。

### 2026-07-26：职业角色被明确为共同畅想的朋友

用户进一步明确，引入职业角色的目的不是让对方评审 DCF 是否完整，也不是模拟某类用户提出功能需求。这个人首先是一位会与用户聊天、被现有构想激发，并真心提出自己设想与愿望的朋友；工作经验、专业规范和个人爱好只是让他的痛点、警惕点、舒适点与兴趣方向不同。

因此，角色视角的价值在于让异质经验自动照见当前愿景没有明确表达的部分和彼此尚未发现的盲区，再以新的生活画面补充和拓展共同世界。被用户接住的联想会融入当前愿景；仅属于这位朋友的偏好仍保留为可能性，不会因为带有专业身份就自动变成产品规范。

### 2026-07-26：QA 视角让可塑世界拥有持续可信的地面

QA 朋友听见“任何软件都能在使用现场被持续改造”以后，首先被吸引的不是增加一套测试与构建功能，而是让用户可以大胆改变数字生活，又不必把已经好用的部分一起押上。他希望每个变化先作为与带条件可信状态并存的候选出现，原实现、适用条件、证据与撤回路径不会丢失；构建、自动检查、模拟结果、真实行为与用户认可各自保留边界，最终启用的也必须是被实际验证过的同一份成果。

这层联想让“可信”从任务结束时的一份报告，变成每项长期能力持续携带的来历、适用条件和新鲜度。环境变化只会使受影响的承诺进入待复验或未知，故障现场则自动成为可接手的证据包，并在修复后长成回归守卫。旧验收仍然服从用户当前认可的愿望，因此既能防止实现悄悄倒退，也不会把用户过去的选择固化成新的牢笼。DCF 由此不承诺永不失败，而承诺不会把未知伪装成成功、不会混淆不同层次的证明，也不会把收集证据和反复复现的负担转嫁给用户。

### 2026-07-26：代码审查员视角让变化保持可理解与可继续

代码审查员朋友在 QA 已经建立的持续可信之上，又看见了一种不同的长期风险：一项改动即使今天通过全部验证，也可能在不显眼之处改变事实所有权、权限边界、依赖关系和未来选择，让个人软件世界在多年个性化以后变成无人敢动的补丁迷宫。他希望每项变化同时携带用户意图、关键判断、语义影响、已接受风险与撤回条件，使代码、决定和证据成为同一段能够由未来 AI 继续阅读的历史。

这层联想让代码审查从逐行找错扩展为保护用户未来自由的能力。DCF 会显出真实修改半径，让严谨程度服从寿命、影响范围和用户价值；审查意见以带条件的风险判断存在，条件未变时不重复打扰，现实改变时再重新出现。多个局部补丁反复指向同一缺失关系时，它还会推动源头收束，使个人能力增加的同时系统仍有机会变得更简单。由此，任何 AI 都可以贡献实现，却没有哪项能力会成为只有原作者才能解释、用户无法替换的神秘遗产。

### 2026-07-26：UI 操作者视角让界面现场可以倒带与重返

UI 操作者朋友在 QA 的持续可信与代码审查员的长期可理解之外，看见了另一类尚未被真正保存的现实：用户在界面中实际经历的异常往往只存在几秒，聊天中的“这里、刚才、这样”很快失去所指，静态截图、内部日志与自动化步骤又各自只能保留其中一层。他希望 DCF 让获准观察的界面中短暂、本机存在的余像可以在用户指认后冻结为最小相关片段，把可见画面、连续动作、焦点与滚动、候选和环境，以及用于解释原因的结构与运行观察对齐成同一个可重新进入的现场；“不读取”的窗口不会产生余像。

这层联想让可视化 Bug 从需要用户反复复现和搬运证据的问题，变成可以由网页 AI、IDE Agent 和用户共同倒带、分层查看、分叉重放与前后比较的现实材料。用户看到的像素事实不会被内部状态覆盖，视觉差异也不会替用户决定审美与手感；真正端到端路径中的观察盲区会明确保留为未知。界面余像默认短暂、本地且克制，只有被选中的最小现场才继承隐私边界进入长期材料。由此，数字世界不仅能够被现场改造，还获得了一种可以回到“刚才那个瞬间”继续工作的记忆。

### 2026-07-26：故障诊断工程师视角让异常获得可证伪的因果解释

故障诊断工程师朋友接住 UI 操作者保存的活现场与 QA 保存的可信证据后，进一步指出：稳定复现仍然只说明某组条件与症状同时出现，不能自动证明最靠近报错的位置就是根因。他希望 DCF 能在同一个故障身份下，从不可改写的真实失败现场分叉出隔离的故障分身，通过变量收缩、成功与失败对照、版本和配置二分以及反事实重放，逐步区分触发条件、潜在缺陷、传播路径和用户症状，直到找到一项被改变后能让整族故障失去成立条件的基础关系。

这层联想让诊断从 AI 对日志的完整叙述，变成一组可以被区分性实验支持、反驳和继续修正的因果假设。恢复用户生活、确认根因、实施源头修复和长期加固分别保留真实状态；修复建议则说明自己准备改变什么、预期消除什么、必须保住什么以及怎样证明没有只遮住症状。相似异常会沿因果关系形成可演化的故障谱系，所需观察探针只在可疑边界临时长出。由此，故障不再只留下一个补丁与一条回归测试，而开始成为 DCF 理解自身边界、收束共同源头并让整类问题自然消失的因果记忆。

### 2026-07-26：上位秩序统一授权、权威与证据

一次全文一致性审查发现，增量续写已经让若干局部愿景拥有了彼此不完全相同的边界与权威。用户确认以一条共同秩序收束全文：DCF 只在用户授权的生活边界内保存现实；AI 基于现实形成带来路的候选；各职业朋友分别保存和证明候选的不同侧面；只有用户能够决定目标、观察边界、价值取舍与最终接纳。由此，“完整记录”被限定在授权范围内，“可信”绑定具体实现、环境与证据，导出的用户可编辑成果拥有唯一当前正文，推荐只有被用户接住后才成为任务，同一故障的 QA 证据、界面现场与诊断分身也被归为一个身份下的不同层次。旧 DCF 的架构与结论不再预设新愿景，但用户过去的生活材料仍可带着来路重新进入。
