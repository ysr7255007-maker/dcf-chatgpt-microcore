# ADR：DCF 认知生长架构——从叙事到知识、任务与行动

日期：2026-08-05  
状态：研究中 / 架构提案  
权威等级：非当前实施规范；用于保存阶段性架构理解与后续讨论材料

> 本文不替代 `docs/spec/2026-08-04-DCF-当前实施规范.md`。  
> 当前实施规范仍回答“现在什么是 DCF”；本文回答“在不破坏现有核心机制的前提下，DCF 未来的叙事、知识、记忆、任务与行动能力可能怎样从同一个根上生长出来”。

> 本文刻意保留“既有 DCF 基础机制”和“本轮新增候选架构”两个层次。后续讨论时，应优先判断新增结构究竟是既有机制的自然展开，还是不必要的额外复杂度。

---

# 1. 为什么现在记录这份 ADR

DCF 当前已经有一套相对清楚的基础机制：

```text
真实交互 / 现实
→ 留下记录与回忆锚点
→ AI 基于当时材料形成一个当前关系叙事
→ 用户回看、复盘、纠正
→ 用户补充本身成为新的认知记录
→ 时间推进，新现实继续进入
→ 旧关系被强化、补漏、修正或重新解释
→ 所有理解变化只追加、不覆盖
```

这一机制解决的是：

> **如何让过去不是一堆死记录，而是一条可以被未来重新进入、重新理解、持续生长的认知历史。**

随着 DCF 继续发展，新的需求逐渐出现：

- 不只生成人物关系叙事，还要生长项目叙事；
- 不只让人回看，还要让 AI 在当前任务中快速获得高密度知识；
- 不只描述已经发生的事情，还要从知识缺口、认知冲突和用户目标中提出未来任务；
- 不只产生任务，还要让 AI 在受控工作环境中执行、验证、恢复，并把结果重新变成新的现实材料；
- 不只保存“当前最好用的知识”，还要保存理解为何发生变化。

因此现在需要一个新的架构问题：

> **叙事、知识卡、当前记忆、任务生成、AI 工作 Harness 等能力，应该各自独立生长，还是共享一个更底层的认知根？**

本文给出的初步答案是：

> **共享长期历史根，但面向不同消费者形成独立的当前状态；当前状态再经过不同规划层进入叙事、知识更新和未来行动。**

这只是当前最有解释力的候选，不是最终定案。

# 2. 必须保留的既有 DCF 基础机制

本轮架构研究不得覆盖以下既有结论。

## 2.1 记录负责唤醒，AI 负责起草，用户负责校准，时间负责纠错

DCF 不要求某一次 AI 对过去形成最终正确解释。

它要求长期保存：

```text
观察过什么
当时怎样理解
后来怎样重新理解
这些理解之间怎样发生转变
```

因此一次后来被证明粗糙甚至错误的理解，只要当时真实形成过，仍然属于认知历史的一部分。

## 2.2 原件可以代谢，认知变化不能被静默抹除

允许：

```text
完整原件
→ 压缩记录
→ 代表性片段
→ 回忆锚点 / 来源标记
```

但已经进入认知历史的意义不能被伪装成“从未发生”。

核心原则仍是：

> **原件可以变轻，认知变化必须变长。**

## 2.3 后来的理解不能偷偷改写过去的理解

如果早期形成理解甲，后来形成理解乙，不应把甲直接改成乙。

应保存：

```text
理解甲
↓
因为新的现实 / 复盘 / 证据 / 人生经历
↓
形成理解乙
```

乙可能是对甲的：

- 延续；
- 补充；
- 修正；
- 重新解释；
- 缩小范围；
- 扩大范围；
- 部分否定；
- 冲突；
- 取代。

其中“取代”只能是一种关系，不能成为默认关系。

## 2.4 用户校准不是质量检查，而是新的认知事件

用户说：

> “我当时其实不是因为性能选择这个方案，而是因为它复杂度最低。”

这不是简单修改一段旧摘要，而是一个新的认知事实：

```text
旧解释存在
↓
用户后来形成新的自我理解
↓
追加新的认知事件
↓
建立与旧解释的转变关系
```

这条纪律对后续 Ripple Wiki、知识卡和任务系统都继续有效。

# 3. 新的总架构假设：DCF 不是一条线，而是“历史根 → 当前状态 → 规划 → 意图 → 行动 → 新现实”

当前最有解释力的候选骨架是：

```text
长期历史层
    ↓
当前状态层
    ↓
规划层
    ↓
未来意图层
    ↓
AI 工作 Harness
    ↓
行动
    ↓
新现实
    ↓
重新进入长期历史层
```

展开为：

```text
                    现实
                     │
                     ▼
               记录与观察
                     │
                     ▼
                 认知谱系
                     │
       ┌─────────────┼─────────────┐
       ▼             ▼             ▼
    当前记忆       当前知识       当前叙事
       │             │             │
       │          知识规划       叙事规划
       │             │             │
       └─────────────┼─────────────┘
                     ▼
                  当前理解
                     │
                  行动规划
                     │
                     ▼
                  任务候选
                     │
                  任务裁决
                     │
                     ▼
                  正式任务
                     │
                     ▼
               AI 工作 Harness
                     │
                     ▼
                    行动
                     │
                     ▼
                   新现实
                     │
                     └──────────────→ 循环继续
```

这张图目前只表达职责关系，不表达施工顺序。

---

# 4. 长期历史层：认知谱系是 DCF 最独特的根

长期历史层保存不能被“当前最好用状态”吞掉的东西。

初步包含：

```text
现实事件
回忆锚点
认知事件
认知转变关系
来源关系
判断规则 / 方法自身的版本变化
```

其中核心是：

> **认知谱系。**

认知谱系回答的不是“现在正确答案是什么”，而是：

```text
发生过什么？
当时怎样理解？
后来为什么改变？
新的理解与旧理解是什么关系？
```

因此它天然允许：

```text
        ┌→ 理解乙
理解甲 ─┤
        └→ 理解丙

理解乙 + 理解丙
       ↓
     理解丁
```

即分叉、合流、冲突、重新解释都允许存在。

这与普通“版本历史”不同：新节点不默认宣告旧节点失效。

---

# 5. 当前状态层：当前记忆、当前知识、当前叙事三分

长期历史适合保存连续性，但不适合每次工作都全量读取。

因此 DCF 需要从长期历史中形成若干“当前可用状态”。

当前候选分为三类。

## 5.1 当前记忆：现在最值得重新想起什么

当前记忆回答：

> **此时此刻，哪些过去经验值得重新进入上下文？**

它允许改变召回地位：

```text
提高召回
降低召回
暂时沉睡
重新唤醒
```

因此 DCF 可以接受：

> **召回可以遗忘，历史不能遗忘。**

退出当前记忆层并不等于删除长期历史。

即使未来当前表示被压缩、删除或替换，也必须留下足够的历史痕迹，证明它曾经存在以及后来怎样变化。

## 5.2 当前知识：现在工作时值得直接使用什么

当前知识主要面向 AI / Agent。

它回答：

> **针对当前现实范围和当前任务，我们有哪些高密度、可直接工作的理解？**

知识卡是当前知识层的主要候选表现形式。

可能包括：

- 模块职责；
- 架构约束；
- 当前设计决定；
- 工具与运行方式；
- 已验证能力；
- 当前风险；
- 重要业务 / 项目术语；
- 与任务相关的经验性知识。

知识卡不是历史真源。

它应该能够从长期历史与当前现实重新形成，也必须能够反向追溯自己由哪些现实事实、用户表达和认知事件支撑。

## 5.3 当前叙事：站在今天怎样连续理解过去

当前叙事主要面向人。

它回答：

> **站在今天，我们怎样把复杂、分叉、甚至互相冲突的认知历史组织成一个人能连续理解的故事？**

因此叙事允许：

- 选择主线；
- 将多个事件压成阶段；
- 将复杂谱系暂时线性化；
- 突出当前最重要的理解路径；
- 为了可读性省略低价值细节。

但叙事只能组织历史，不能反向修改历史。

# 6. 同根但独立：知识卡与 Ripple Wiki 不要求互相派生

当前不再假设：

```text
知识卡 → Wiki
```

也不假设：

```text
Wiki → 知识卡
```

更合理的候选是：

```text
                 长期历史根
          现实记录 + 认知谱系
                   │
        ┌──────────┴──────────┐
        ▼                     ▼
     当前知识               当前叙事
     知识卡                 Ripple Wiki
        │                     │
   独立维护当前态         独立维护当前态
        │                     │
        └──────────┬──────────┘
                   │
               都能追溯历史根
```

原因是两个消费者的需求不同：

```text
AI / Agent
→ 高密度、单义、容易定位、容易组合

人
→ 连续、可读、有上下文、有因果与成长感
```

不应为了共用一种表示而让两端都妥协。

但二者应共享来源与认知历史，使“当前机器知识”和“当前人类叙事”仍然属于同一个 DCF 世界。

---

# 7. 多切面知识：不要强迫知识坍缩成一棵目录树

本轮研究提示，项目知识可能天然同时拥有多个切面。

例如：

```text
模块切面：
这个模块是什么？

主题切面：
这个项目整体怎样构建？
怎样管理依赖？
有哪些业务术语？
怎样处理错误？
```

未来 DCF 知识卡不应过早规定只能：

- 按目录；
- 按模块；
- 按主题；
- 按时间；
- 按任务。

更可能是：

> **同一现实允许形成多个正交知识切面，检索与规划层负责在需要时组合。**

是否需要显式建立切面间关系，暂不决定。

---

# 8. 局部隔离 + 全局连续

不同现实范围可能同时拥有互相冲突、但各自在本地成立的当前知识。

例如：

```text
主分支
实验分支
旧稳定分支
不同设备 / 不同运行环境
```

因此不应该把所有当前知识强行合并成一个全局状态。

候选原则是：

> **当前状态按现实范围局部隔离；认知历史在更高层保持全局连续。**

示意：

```text
                    跨范围身份
                        │
              ┌─────────┴─────────┐
              ▼                   ▼
          主线当前态           实验当前态
              │                   │
              └─────────┬─────────┘
                        ▼
                  跨范围认知谱系
```

这样既防止不同现实互相污染，又能记录：

```text
主线理解甲
↓
在实验范围探索理解乙
↓
实验结果形成理解丙
↓
后来回灌主线形成理解丁
```

---

# 9. 三种规划：叙事规划、知识规划、行动规划

本轮新增的一个重要候选是：

> **生成之前先有规划。**

规划不是最终内容，而是决定“这一轮该怎样组织、该补什么、该往哪里走”。

## 9.1 叙事规划：现在准备怎样讲

它回答：

```text
这次叙事关注什么？
哪些阶段值得展开？
哪些关系是主线？
哪些旧段落受到新现实波及？
```

因此 Ripple Wiki 更可能是：

```text
当前历史与叙事状态
↓
叙事规划
↓
局部生成 / 局部更新
↓
新的当前叙事
```

而不是把全部历史直接交给 AI 自由重写。

## 9.2 知识规划：现在需要知道什么

它回答：

```text
为了当前任务，需要哪些知识？
哪些知识卡已经足够？
哪些需要刷新？
哪些知识缺口需要补充调查？
```

这使知识卡不是无限增长的百科，而是围绕现实和工作需求持续形成的当前机器知识。

## 9.3 行动规划：接下来值得做什么

它回答：

> **当前认知、当前知识、用户目标之间还有哪些缺口值得转化成未来动作？**

输出首先不是正式任务，而是：

```text
任务候选
```

---

# 10. 任务生成：从“我们知道什么”跨到“接下来做什么”

知识与任务不能混为一个对象。

例如：

```text
当前知识：
某恢复机制目前只在人工故障注入中验证过

认知缺口：
尚无真实故障窗口中的长期有效性证据

任务候选：
未来真实故障发生时，记录恢复过程并重新评估长期有效性
```

这是三个不同对象：

```text
我们知道什么
≠
我们认为缺什么
≠
我们准备做什么
```

因此任务生成的候选来源可能包括：

- 用户明确目标；
- 知识缺口；
- 认知冲突；
- 未验证假设；
- 失败后的残差；
- 叙事中尚未闭合的问题；
- 现实中出现的新机会。

---

# 11. 任务候选与正式任务分离

AI 认为“值得做”，不等于 DCF 已经决定“去做”。

候选流程：

```text
认知 / 知识 / 用户目标
↓
行动规划
↓
任务候选
↓
价值、权限、优先级与现实条件裁决
↓
正式任务
```

只有正式任务才能进入执行层。

任务必须保留自己的来源，能够回答：

> **为什么会有这个任务？**

例如追溯到：

```text
某个用户目标
某条认知冲突
某张当前知识卡
某个未验证假设
某次现实失败
某段项目叙事中的未闭合问题
```

这样任务不会变成失去意义来源的孤立待办事项。

---

# 12. AI 工作 Harness 的位置

DCF 可以拥有自己的 AI 工作 Harness，但 Harness 不等于 DCF。

Harness 负责：

```text
给 AI 什么上下文
允许什么工具
拥有什么权限
怎样分解 / 执行
怎样验证
怎样恢复
怎样留下运行证据
```

而 DCF 更高一层负责：

```text
为什么产生这个任务
执行前我们怎样理解世界
执行后现实发生了什么
新的现实怎样改变认知历史
```

因此：

> **Harness 负责把“已经决定要做的事”可靠地变成行动，但无权单独决定这个任务为什么值得存在。**

---

# 13. 行动只产生新现实，不能直接宣布新知识为真

这是本 ADR 中需要重点保留的一条边界。

错误路径：

```text
Agent 执行成功
↓
直接把知识改成“长期有效”
```

候选正确路径：

```text
正式任务
↓
AI 工作 Harness
↓
行动
↓
现实发生变化
↓
DCF 重新观察
↓
形成新的事实 / 证据 / 认知事件
↓
认知谱系继续生长
↓
重新形成当前记忆 / 当前知识 / 当前叙事
```

即：

> **执行系统只能制造新的现实，认知系统再解释这些现实意味着什么。**

---

# 14. 溯源锚与演化历史分离

本轮研究进一步明确两个容易混淆的问题：

```text
“这条认识来自哪里？”
```

与：

```text
“这条认识后来怎样变化？”
```

不是同一件事。

因此 DCF 后续应区分：

## 14.1 溯源锚

负责指回：

- 哪次对话；
- 哪段原文；
- 哪个文件；
- 哪次运行；
- 哪个提交；
- 哪个用户表达；
- 哪个现实事件。

## 14.2 演化历史

负责记录：

```text
何时形成
何时改变
为何改变
与旧理解是什么关系
当前地位怎样变化
```

二者互补，但不能合并成一个字段或一种日志。

---

# 15. 机械操作账本与认知谱系分离

实现层可能需要机械操作账本，例如：

```text
创建
修改
召回
评估
归档
删除当前表示
```

这些操作有工程价值，但不能替代认知谱系。

机械账本回答：

> **状态怎么改过？**

认知谱系回答：

> **理解为什么发生变化？**

DCF 可以保留前者作为基础设施，但长期真正保护的是后者。

因此不承诺永远保存每一次完整前后字节快照。

允许机械历史代谢，只要：

> 已进入认知历史的意义、来源与转变关系仍然可以被恢复和理解。

---

# 16. 证据、认识地位与知识内容分离

本轮暂不固化具体数据结构，但需要保留几个方向。

## 16.1 内容身份不等于权威，不等于正确

```text
内容身份
≠
知识权威
≠
知识正确性
```

一个内容摘要只能回答“是不是同一份内容”，不能回答“这份内容是否可信”。

## 16.2 认识程度与好坏评价不是一个轴

一条能力可以：

```text
确实存在
确实接通
确实运行过
```

但运行结果仍然可能很差。

因此“我们知道到了什么程度”和“它表现好不好”必须分开。

## 16.3 负空间不能全部坍缩成“没有”

未来可能需要区分：

```text
确认缺失
当前无法观察
此问题不适用
```

这类认识论状态是否进入基础 DCF，暂不决定。

## 16.4 不同知识类型允许不同证据门槛

例如：

```text
用户明确目标
→ 用户明确表达即可

当前代码结构
→ 实际检查源码

运行能力
→ 真实运行

效果判断
→ 有结果支持

长期有效性
→ 后续可比较现实窗口继续支持
```

具体知识类型注册表与规则仍属研究项。

---

# 17. 方法本身也有历史

如果未来 DCF 使用：

- 知识分类规则；
- 证据门槛；
- 叙事生成规则；
- 任务生成规则；
- 评价模型；

这些规则不能静默漂移。

候选原则：

> **一次评价 / 生成窗口内规则固定；规则自身变化必须显式版本化，并留下为什么改变的历史。**

即：

```text
认识规则 第一版
↓
为什么改变
↓
认识规则 第二版
```

这使 DCF 不只保存“我们知道了什么”，还能够保存“我们曾经怎样判断自己知道什么”。

---

# 18. Qoder 架构考古给出的启发，但 Qoder 不是设计权威

本 ADR 的部分候选结构来自对 Qoder Better Harness、Knowledge Engine、Repo Wiki、Memory 的本机架构考古。

研究目标不是复制 Qoder，而是借真实系统发现新的边界。

当前吸收 / 修改关系大致如下：

| Qoder 中观察到的模式 | DCF 当前态度 |
| --- | --- |
| 面向机器与面向人的知识状态分离 | 继承，但共同追溯 DCF 长期历史根 |
| Wiki 生成前存在显式规划结构 | 继承为“叙事规划”候选 |
| 不同现实范围维护独立当前知识 | 继承“局部隔离” |
| 不同现实范围之间缺少一等连续关系 | DCF 增加“全局认知连续” |
| Memory 当前行 + 操作账本 | 继承身份与操作历史分离，但新增认知谱系语义层 |
| 召回频率 / 保留分等软遗忘 | 借鉴为“当前召回可遗忘” |
| 冲突后覆盖 / 删除当前记忆 | 不作为 DCF 长期历史模型；DCF 保存认知转变 |
| Memory 到 Knowledge 未观察到一等来源链 | DCF 当前知识必须可反查认知来源 |
| 系统规则显式版本治理 | 借鉴为“方法自身有历史” |
| Better Harness 的证据与判断权限分层 | 作为未来 DCF 证据治理与 Harness 的研究材料 |

Qoder 的任何内部文件名、命令名、字段名仅作为外部证据保留原貌。

DCF 自己拥有的概念、变量、字段、状态、关系和代码标识继续遵守中文优先原则。

---

# 19. 目前明确属于“既有原则”的内容

下列内容不是本轮 Qoder 研究才产生，不能因为未来架构调整而轻易删除：

1. DCF 的根是持续生长的认知历史，而不是单纯存档；
2. 记录负责唤醒，AI 负责起草，用户负责校准，时间负责纠错；
3. 原件可以代谢，认知变化历史不得被静默覆盖；
4. 后来的理解必须追加，不能偷偷改写过去的理解；
5. 用户校准本身属于新的认知事件；
6. 叙事可以高度概然，但事实、推断和用户意图不能混成同一层；
7. DCF 自有命名中文优先，外部协议停在边界。

---

# 20. 目前仍属于“候选架构”的内容

下列内容是本轮研究后形成的高价值候选，后续可以讨论、合并、简化甚至推翻：

1. “长期历史层 → 当前状态层 → 规划层 → 未来意图层 → Harness → 现实回流”的六段结构；
2. 当前记忆、当前知识、当前叙事三分；
3. 知识卡与 Ripple Wiki 同根但独立维护当前态；
4. 叙事规划、知识规划、行动规划三分；
5. 局部现实隔离 + 全局认知连续；
6. 当前知识必须反向追溯长期认知来源；
7. 任务先以候选存在，经过裁决后才成为正式任务；
8. 任务必须保留“为什么产生”的来源；
9. 行动只产生新的现实，不直接宣布知识为真；
10. 当前召回可以遗忘，但认知历史不能被伪装成从未发生；
11. 方法 / 判断规则自身需要显式版本历史；
12. 证据治理可能需要进一步引入认识程度、负空间状态和按知识类型区分的证据门槛。

---

# 21. 当前故意不决定的实现问题

本 ADR 不决定：

- 认知谱系是否使用图数据库；
- 关系类型最终全集；
- 知识卡具体字段与数据库结构；
- 当前记忆具体召回算法；
- Ripple Wiki 的存储格式；
- 叙事规划如何表示；
- 知识规划是否长期保存；
- 任务状态机；
- 任务自动批准规则；
- AI 工作 Harness 的具体实现；
- 是否使用多 Agent；
- 知识波及 / 失效传播算法；
- 证据状态是否进入基础数据模型；
- Qoder 任一具体实现是否复用。

原因：当前目标是先把“各能力为什么存在、各自拥有什么权力、彼此通过什么边界连接”讨论清楚，而不是让实现细节提前冻结架构。

---

# 22. 后续讨论建议：先拿本 ADR 与旧 DCF 基本机制逐项对照

下一轮讨论不应继续扩充架构。

建议先回到最简单的基础闭环：

```text
真实交互
→ 回忆锚点
→ AI 当前关系叙事
→ 用户校准
→ 新认知记录
→ 时间与新现实
→ 旧关系被强化 / 补漏 / 修正 / 重新解释
→ 理解变化只追加
```

然后逐项问：

```text
“当前记忆”是这个闭环里原本已经存在但没有命名的东西，
还是新加的一层？

“当前知识”与原来的关系叙事究竟有什么本质区别？

“叙事规划”是否真的需要独立存在，
还是原来 AI 起草叙事过程里的一个内部步骤？

“知识规划”是不是必要架构，
还是为了模仿 Qoder 才多出来的抽象？

“任务候选 → 正式任务”是否属于 DCF 本体，
还是行动扩展？

AI 工作 Harness 应该属于 DCF 的哪一层，
拿掉以后系统还配不配叫 DCF？
```

这些问题比继续添加新概念更重要。

---

# 23. 当前一句话版本

现阶段对未来 DCF 的最简候选描述是：

> **DCF 以不可静默覆写的认知谱系保存长期连续性，从中形成面向当下的记忆、知识与叙事，再把当前理解经过规划转化为未来任务；任务通过 AI 工作 Harness 改变现实，新的现实重新进入认知历史。**

但本文同时保留一个更重要的审查问题：

> **这套结构里哪些只是我们给原有简单闭环重新起了名字，哪些真的解决了原机制无法解决的问题？**

后续讨论应以这个问题为主，而不是默认接受本文全部候选层级。
