# ADR: DCF 采用最小活闭环生长路线

Date: 2026-07-26
Status: accepted and executable

## Context

`docs/vision/2026-07-26-dcf-from-zero-vision-adr.md` 已经重新声明 DCF 的价值目标：在用户授权边界内保存现实，让认知、成果与行动能够跨时间、AI 和工具继续，同时保持透明、可恢复、可替换和可迁移。

旧 DCF 已经积累了一套可运行的 Chrome 实现、数据连续性、恢复与控制面经验。但旧实现的目录、插件划分和控制对象不是新系统的预设架构。此前一版实施设想又过早引入通用 ObjectIdentity、通用 DORC 状态机、双控制面、多套持久化和固定专家流水线，先建平台再寻找生活价值。

本 ADR 撤回该路线。新系统先让一段真实对话完成：

```text
授权 → 收回 → 保存 → 回看
```

后续结构只在真实使用产生需要时生长。

## Responsibility

用户拥有愿景、价值目标、观察边界和现实体验的最终事实，不是工程审批者。

执行层负责：

- 分支归一、提交、标签、目录和命名；
- 技术选型、协议细节、桌面承载和打包；
- 开工条件、测试、结构化取证和可逆回退；
- 在未知出现时继续调查，选择可逆路线并保留证据。

无法证明的状态必须保持为 `unknown`、`unverified`、`blocked`、`not_tested` 或 `failed`。内部不确定性不能被转换成用户缺乏判断基础的选择题。用户自然使用中的反馈校准价值和行为结果，不构成工程开工许可。

交付始终包含：

```text
执行结果 + 证据 + 仍然真实存在的未知
```

## Decision

### 1. 旧世界归一

在新代码进入主线前：

1. 获取最新远端事实并生成 dry-run 证据；
2. 选出最后完整、可运行且保留设计依据的旧世界实现；
3. 保留准确旧世界检查点和分叉路线；
4. 将旧世界历史与当前愿景共同归入 `main`；
5. `stable` 在新系统获得真实行为证据前保持不动；
6. 新系统只在顶层 `seed/` 生长，旧实现不再被渐进改造成新系统。

P0 的实际 SHA、分支关系、验证结果和未取得的本地工件记录在 `seed/docs/p0-unification-evidence.md`。

### 2. 三层责任

#### Companion Core

`seed/companion/` 是唯一持久核心：

- 保存全部权威材料事实与版本化边界关系；
- 持有长期连续性；
- 接受适配器提交的观察事件；
- 生成可重算投影和缺口事实；
- 为 DCF Surface 提供查询与操作接口。

#### DCF Surface

`seed/surface/` 是 DCF 自己拥有的统一显性界面，不从属于 Chrome、某个网页、IDE 或本地 AI。

G1 的极简回看页是 Surface 的第一块。搜索、取用、发射、边界管理和任务状态以后继续长在同一界面。具体桌面承载容器在 G2 前依据真实技术侦察选择，容器不拥有 Surface 的业务事实。

#### Target Adapter

`seed/adapters/chrome/` 从 Chrome 起步，只负责：

- 静默观察获准现场；
- 把通用意图翻译成目标动作；
- 维持显式目标绑定；
- 返回动作结果和证据；
- 暂存尚未被 companion 确认接收的最小传输事件。

Target Adapter 不持有权威材料、投影、任务状态或 DCF 业务界面。

### 3. 身份与存储

- 持续演化的对话、话题、卡片、任务和故障使用稳定、不透明的 `EntityID`；
- 不可变正文、快照和附件使用 SHA-256 内容寻址；
- 来路、隐私边界和归属是版本化关系，不进入对象身份；
- 第一版只有一个 SQLite：append-only 原始事实表与可重算投影表共存；
- 附件外置内容寻址；
- G2 需要搜索时使用 FTS5；
- 不建立备用 JSONL 引擎、第二 SQLite 或浏览器端业务数据库。

### 4. 浏览器 durable outbox

唯一权威写入者不等于浏览器只能使用易失内存。Chrome 适配器拥有一个有界 durable outbox，定位为非权威传输保管：

- 只保存尚未被 companion 确认提交的最小观察事件；
- 事件具有稳定事件身份和来源顺序；
- companion 仍是唯一材料事实 writer；
- 收到提交确认后删除对应副本；
- 不提供材料查询、投影或业务状态；
- 达到容量边界时不得无限增长，未能保留的范围形成诚实缺口；
- 重复投递由稳定事件身份吸收，不生成第二份材料事实。

### 5. 授权边界

第一天即实现三态授权：

- `不读取`
- `只用于当前`
- `允许归档`

默认是 `只用于当前`。边界是 companion 保存的一级版本化关系，衍生产物继承边界。

`不读取` 的零残留语义限定为内容零残留：正文、附件、DOM 快照、派生材料、遥测载荷和临时观察均不得保存。为持续执行排除决定所必需的最小边界关系可以持久化。用户主动排除不属于缺口。

### 6. DORC 的边界

Desired / Observed / Committed / Reconcile 只作为事实所有权检查法：

- 每份重要事实只有一个 writer；
- 观察不能冒充承诺；
- 不从页面、焦点、外部程序目录或易失内存推测用户目标；
- 只有真实存在 Desired / Observed / Committed 的领域才实现自己的最小闭环。

新系统不建立一个可以承载所有业务的通用 DORC 状态机。

### 7. 生长顺序

#### G1：活闭环

三态授权 → Chrome 捕获真实 ChatGPT 对话 → durable outbox 保管未送达事件 → companion 持久保存 → 刷新、崩溃和短暂离线后恢复 → DCF Surface 回看完整对话、来路、边界和缺口。

#### G2：显性界面

同一 DCF Surface 长出卡片架、FTS5 全域搜索、原始现场回跳、当前目标边界显示和切换。G2 出口前 companion 必须成为自带运行时、自动启动和恢复的完整伴生程序。

#### G3：材料代谢与可迁移成果

复用已接入的 ChatGPT 作为第一个 AI 执行者，生成修订候选和续接点，不覆盖原件。主张归属必须区分 AI 提出、用户试探、用户确认和现实验证。GitHub 中允许用户编辑的文件拥有当前正文，DCF 只生成三向合并修订候选。

#### G4：核心生命循环

区分卡片、火花、带理由的推荐和任务。推荐只有被用户接住后才成为任务。Companion 持有任务目标、来路、边界、进度和检查点；当前明确绑定的 ChatGPT 会话是第一个判断者与执行者。结果、失败路线和认识变化分别回灌所属材料关系。

#### G5：跨执行者协作

把 G4 已成立的协议扩展到 IDE Agent 和本地 AI。执行者可以替换并从真实进度接手；会话和工作区使用显式绑定，不从焦点或当前目录推测。

#### G6：个人软件修改

个人补丁同时携带原始意图、适用现场、当前实现、行为验收和撤回办法。候选与现状并存，真实使用认可后才接替；环境变化只让被触及的承诺进入需要复验或未知。

#### G7：高级观察能力

界面余像、故障分身、因果诊断和故障谱系只在 G6 运行中出现现有证据无法定位的真实故障后开工。

依赖严格为：

```text
P0 → G1 → G2 → G3 → G4 → G5 → G6 → G7
```

### 8. 验证

- `seed/tests/` 使用与仓库规模相称的确定性测试，随行为同步生长；
- 新行为先写能够因缺失行为而失败的测试，再实现最小代码；
- G1 起常设三条红线：内容零残留、缺口如实性、outbox 非权威性；
- 用户可见闭环必须通过真实浏览器行为验收并自动生成结构化证据；
- 触及事实所有权、隐私边界或不可逆动作时提高审查强度；
- 旧世界 `test:chrome` 和 `test:legacy` 在新系统生长期间保持绿色；
- 每环只实现本环所需 schema 和接口，为未来环预铺平台结构视为跑偏。

## Consequences

- 第一份新代码必须直接服务 G1，而不是脚手架展示；
- DCF Surface 与承载容器解耦，Chrome 适配器保持静默；
- 浏览器可持久保管未送达事件，但不能成为第二材料事实源；
- Companion 失联、MV3 休眠和重复投递有同一条可解释恢复路径；
- 旧实现作为可运行历史保留，不承担新系统的演化负担；
- G2 之前允许 Node 直跑，但用户开始日常依赖前必须吸收运行时与启动复杂度。

## Rejected alternatives

- 通用内容寻址 ObjectIdentity；
- 通用 DORC 业务状态机；
- Service Worker 与 companion 双控制面；
- `chrome.sidePanel` 作为 DCF 本体；
- 仅内存传输缓冲；
- IndexedDB 业务队列、JSONL 降级或双 SQLite；
- 固定证据层数和固定专家流水线；
- 纯脚手架里程碑；
- 在核心生命循环前建设界面余像和故障分身；
- 在 G3/G4 预建模型调度平台。

## Reconsideration

仅当真实证据表明以下任一事实成立时重新设计相关边界：

- 有界 durable outbox 无法在 Chrome 生命周期下可靠保存最小未送达事件；
- 单 SQLite 无法同时承载原始事实和可重算投影；
- DCF Surface 无法在不依附单一目标平台的前提下形成可用承载；
- Native Messaging 或替代接入通道无法在日常使用中实现自动恢复；
- G1 的真实使用证明三层责任仍把内部复杂度转嫁给用户。
